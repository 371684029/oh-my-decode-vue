# 低代码前端平台 (Low-Code Frontend Platform) - 0.0.1 规划文档

## 1. 项目概述与愿景

### 1.1 项目简介
本项目旨在打造一款高性能、高可扩展性、高度模块化的**低代码前端可视化平台**。用户可以通过可视化拖拉拽的方式快速搭建前端页面，或者将常用的 UI 与逻辑封装并导出为可复用的前端 JS/Vue 组件。

### 1.2 核心目标 (0.0.1 版本)
- **可视化拖拽搭建**：集成网格布局引擎，实现拖拽组件投射到画布并自由伸缩定位。
- **动态属性与样式配置**：提供右侧属性面板，实时绑定并修改 UI 组件的属性、样式及响应式数据。
- **页面与组件无缝切换**：既支持独立完整页面的搭建，也支持将组合节点导出为独立前端 JS/Vue 组件。
- **出码能力 (Code Generation)**：支持将低代码 JSON Schema 一键生成高可读性、符合 Vue 3 官方规范的 `.vue` 源码文件。
- **工程质量标准**：严谨的代码结构、强类型定义、高度组件化解耦、极致的代码可读性与可维护性。

## 3. 核心设计规范与 Schema 结构

系统核心由 **JSON Schema** 驱动，实现 `Schema <-> 画布渲染 <-> 源码生成` 的双向转换。

### 3.1 页面/组件 Schema 规范 (`PageSchema`)

```typescript
export interface PageSchema {
  id: string;             // 页面或组件唯一 ID
  title: string;          // 名称
  type: 'page' | 'component'; // 标注是完整页面还是自定义组件
  meta: {
    author: string;
    description: string;
    version: string;
  };
  // 页面全局状态定义
  state: Record<string, any>;
  // 网格布局容器及节点列表
  children: ComponentNode[];
}

export interface ComponentNode {
  id: string;             // 节点唯一 ID
  type: string;           // 组件类型 (例如: 'el-button', 'el-input', 'custom-card')
  label: string;          // 物料显示名称
  // vue3-grid-layout 位置与尺寸配置
  layout: {
    x: number;            // 网格 X 坐标
    y: number;            // 网格 Y 坐标
    w: number;            // 网格宽度 (栅格列数)
    h: number;            // 网格高度 (栅格行数)
    i: string;            // 布局唯一标识 (一般同 id)
  };
  // 组件原生/自定义属性
  props: Record<string, any>;
  // 自定义内联样式/CSS类
  style: Record<string, any>;
  // 事件绑定 (如 onClick, onChange)
  events: Record<string, EventHandler>;
  // 子节点 (支持容器嵌套)
  children?: ComponentNode[];
}

export interface EventHandler {
  type: 'custom_js' | 'page_jump' | 'open_modal';
  code?: string;          // 自定义 JS 代码段
  target?: string;
}
```

## 5. 后端 SQLite 数据模型设计

SQLite 数据库设计注重简洁与扩展性：

### 5.1 `pages` (页面/组件存储表)
| 字段名 | 类型 | 约束 | 描述 |
| :--- | :--- | :--- | :--- |
| `id` | VARCHAR(36) | PRIMARY KEY | 页面/组件 UUID |
| `name` | VARCHAR(100) | NOT NULL | 页面或组件名称 |

| `updated_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 更新时间 |

## 7. 代码与质量规范 (Quality & Style Guide)

1. **强类型与严谨声明**：
   - 所有 Schema 数据结构必须有完备的 TypeScript interface / type 定义。
   - 避免使用 `any`，确保配置变更时有完备的编译时提示。

2. **严格组件化与单职责原则 (SRP)**：
   - 设计器拆分为 `MaterialList`, `CanvasContainer`, `GridItemWrapper`, `PropertyEditor`, `CodePreviewModal` 等单一职责小组件。
   - 物料属性配置器采用表单项工厂模式 (`SetterFactory`)，支持按类型（如字符串、数值、选择器、颜色）动态匹配。

3. **可维护性与扩展性**：
   - 新物料接入只需在 `registry` 注册元数据（包含默认属性、配置面板 schema），实现零侵入拓展。
   - 前后端代码排版规范统一（ESLint + Prettier），变量与函数采用语义化英文命名。
