# 低代码前端可视化平台 (Low-Code Studio) - v0.5.0 规划文档

> **版本定位**：多工作区多项目管理、自制组件入参/出参规范强校验、简易操作日志可视化控制台
> **状态**：规划中 (Drafting)
> **前置版本**：v0.0.1 (基础平台与双存储), v0.2.0 (出码/自动保存/快捷键), v0.3.0 (响应式多端/嵌套/表达式), v0.4.0 (逻辑流/数据源/物料SDK)

---

## 🎯 0.5.0 核心目标

在项目逐步具备高级逻辑编排与物料扩展能力的基础上，0.5.0 专注于**多项目工程组织**、**自制组件入参/出参标准化强约束**与**系统可追溯性**，解决团队多人协作下的项目混乱、自定义物料入参不规范导致运行时崩溃、以及缺乏可视化操作审计的问题。（注：复杂的 RBAC 权限系统暂不涉及，放在后续版本规划）。

---

## 📋 功能清单与演进规划

### 1. 多工作区与多项目隔离系统 (Multi-Workspace & Project System)
- **目标**：引入“工作区 (Workspace) -> 项目 (Project) -> 页面/组件 Schema”的三层组织架构，实现项目级别的物理隔离与快速切换。
- **功能特性**：
  - **工作区管理 (Workspace Management)**：支持创建/切换/编辑工作区（例如：`研发部-内部系统工作区`、`营销部-活动页工作区`）。
  - **项目目录 (Projects Directory)**：每个工作区下可创建多个独立项目，各自拥有独立的页面列表、公共组件库与数据源配置。
  - **后端存储目录隔离**：Backend 存储结构优化为 `backend/storage/workspaces/{workspace_id}/projects/{project_id}/pages/*.json`。

### 2. 自制组件入参/出参规范强校验契约 (Mandatory Component I/O Parameter Contract)
- **目标**：规范自定义物料（Custom / Pro Components）的数据输入输出，对入参 (Inputs / Props) 与出参 (Outputs / Emits) 实施**必填定义与类型强校验**，避免运行时数据绑定异常。
- **功能特性**：
  - **入参 (Inputs / Props) 规范**：每个自制组件必须显式申明参数名称、数据类型（String, Number, Boolean, Array, Object）、默认值、是否必填（`required: true`）及校验规则。
  - **出参 (Outputs / Emits) 规范**：显式定义组件向上抛出的事件名称、触发时机及 Payload 参数 Schema 约束。
  - **设计器属性抽屉强提示**：当用户在拖拽画布中配置了带有必填入参的自制组件但未填入参数或类型不匹配时，属性抽屉及画布该节点上呈现显目高亮警告。

### 3. 可视化简易操作日志控制台 (Simplified Audit Log Console)
- **目标**：对 SQLite 数据库中记录的审计日志进行可视化展示，方便管理员快速查阅操作历史、追溯谁在什么时间改动了什么页面。
- **功能特性**：
  - **日志列表展示**：提供专用的日志弹窗/控制台，展示包含 `日志ID`、`操作时间`、`工作区/项目`、`页面ID`、`操作类型`（新建/保存/删除）、`操作人` 及 `变更节点数` 的表格。
  - **快速筛选与搜索**：支持按时间范围、操作人、页面名称及操作类型进行模糊检索。
  - **改动详情 JSON 预览**：点击日志行可展开查看该次操作对应的 Schema 变更摘要 JSON。

## 🏗️ 存储与 API 接口变更演进

1. **工作区存储接口**：
   - `GET /api/workspaces` - 获取工作区列表
   - `POST /api/workspaces` - 创建工作区
   - `GET /api/workspaces/:wsId/projects` - 获取指定工作区下的项目列表
2. **操作日志查询接口扩展**：
   - `GET /api/logs?workspaceId=xxx&projectId=yyy&keyword=zzz` - 分页与多维度筛选日志
