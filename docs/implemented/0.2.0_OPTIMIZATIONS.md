## 1. Web Component 样式隔离与 UI 库样式注入

### 1.1 当前问题
在 v0.2.0 中，Web Component 导出使用 Vue 3 官方 `defineCustomElement` API。由于其默认开启 **Shadow DOM 隔离**，Element Plus 等第三方 UI 库的全局 CSS 样式（如 `.el-button`）无法自动穿透入 Shadow Root 内，可能导致导出的自定义元素呈现无样式的纯文本。

### 1.2 优化方案
* **样式注入方案 (Style Injection)**：在生成 Web Component 代码时，将 Element Plus 核心 CSS 提取并通过 `styles: [elementCssText]` 注入 `defineCustomElement` 配置中：
  ```javascript
  import elementPlusCss from 'element-plus/dist/index.css?inline';
  const CustomElement = defineCustomElement({
    ...ComponentConfig,
    styles: [elementPlusCss]
  });
  ```
* **Light DOM 兜底模式**：对不需要 Shadow DOM 隔离的场景，提供无 Shadow DOM 挂载配置，让自定义元素直接继承宿主页面的 CSS。

## 2. 增量差分保存与网络 IO 性能优化

### 2.1 当前问题
当前 3 分钟防崩溃静默保存功能采用的是**全量 PageSchema 序列化**提交（`POST /api/schemas`）。当页面组件多达数百个时，每次自动保存都会产生数兆字节的 JSON 请求 Payload，造成不必要的网络开销与磁盘写入 IO 压力。

### 2.2 优化方案
* **引入 RFC 6902 JSON Patch 增量保存**：
  - 前端维护上一次提交成功时的 Schema 快照 `lastSavedSchema`。
  - 定时保存触发时，通过 `createPatch(lastSavedSchema, currentSchema)` 计算出轻量级的 Patch 差异数组：
    ```json
    [
      { "op": "replace", "path": "/children/0/props/text", "value": "新按钮文本" }
    ]
    ```
  - 发送 `PATCH /api/schemas/:id` 请求，后端仅应用 Patch 并落盘 SQLite 审计日志，显著减少 90%+ 的传输数据量。

## 3. 撤销/重做历史栈内存精细化管理

### 3.1 当前问题
v0.2.0 在 Pinia `designerStore` 中使用 `historyPast` 与 `historyFuture` 数组存储全量 JSON 字符串快照（限制 30 步）。虽然简单可靠，但在长时间高强度的拖拽编辑下，频繁的 `JSON.stringify` / `JSON.parse` 仍然会产生一定的垃圾回收 (GC) 压力。

### 3.2 优化方案
* **基于数据结构浅拷贝或不可变数据 (Immutability)**：使用 `Immer.js` 或变动 Patch 记录，仅保存产生修改的 DOM 节点与 Layout 位置信息。
* **空变动过滤**：防抖（Debounce）拖拽调整过程中的中间状态，仅在松开鼠标（`dragstop` / `resizestop`）后才记录一步最终历史快照。

## 4. 快捷键作用域精准控制与事件冒泡拦截

### 4.1 当前问题
v0.2.0 增加了 `Ctrl+C`、`Ctrl+V`、`Delete`、`Ctrl+Z` 快捷键，并对输入框 (`INPUT` / `TEXTAREA`) 进行了基础跳过拦截。然而，当打开第三方对话框（如属性面板中的 Monaco 代码编辑器，或 Element Plus 内部的多功能 Cascader 级联选择器）时，按 `Delete` 或 `Backspace` 仍有可能误删画布上的组件。

### 4.2 优化方案
* **快捷键 Context Manager 机制**：
  - 维护全局 Pinia 响应式标志 `activeModalCount` 或 `focusedZone`（如 `'canvas' | 'drawer' | 'dialog'`）。
  - 仅当 `focusedZone === 'canvas'` 且无活跃 Modal 打开时，才响应该画布级别的组件删除与复制快捷键。

## 5. 出码引擎格式化美化与 Prettier 引擎集成

### 5.1 当前问题
当前 `codeGenerator.ts` 导出的 Vue 3 SFC 和 HTML 是基于字符串拼接模板生成的，对于多层嵌套表单，缩进可能不够整齐。

### 5.2 优化方案
* **前端集成 Prettier Standalone**：
  在客户端加载 `prettier/standalone` 与 `prettier/parser-html`、`prettier/parser-babel`：
  ```typescript
  import prettier from 'prettier/standalone';
  import parserHtml from 'prettier/parser-html';
  import parserTypescript from 'prettier/parser-typescript';

  export function formatCode(rawCode: string): string {
    return prettier.format(rawCode, {
      parser: 'vue',
      plugins: [parserHtml, parserTypescript],
      singleQuote: true,
      semi: true
    });
  }
  ```
  在用户点击“导出代码”时，先经过 Prettier 动态美化，确保输出的代码达到高级工程师手写级别的严格代码规范。
