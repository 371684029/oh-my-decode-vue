# v2.1.0 物料版本管理与黑盒引用规划 (Material Versioning & Black-box Reference)

> **文档定位**：v2.1.0 版本规划 —— 复合物料从 v2.0.0 的"展开模式"升级为"黑盒引用模式"，引入物料版本管理。
> **状态**：规划中 (Draft / 待评审)
> **前置版本**：v2.0.0（自我循环物料机制，规划已定）

---

## 一、目标与定义

### 1.1 一句话目标

**复合物料升级为"黑盒引用"：画布上的实例引用物料定义（`materialRef`），物料演进以版本管理——发布新版本、实例显式升级、可回滚、可对比差异。让"自己生成的组件"像正式组件库一样有版本纪律。**

### 1.2 为什么版本管理放在 v2.1（而不是 v2.0）

v2.0.0 的展开模式中，拖入物料 = 扁平化展开为普通节点子树，**实例与定义零运行时引用**——改物料只是改模板，不影响任何已拖入实例，因此版本无运行时语义（已在 v2.0 决策点明确不做）。

黑盒引用模式改变了这一点：**实例引用物料定义**，定义演进会传播到实例。版本管理从"可选元信息"变为"必要机制"：

- 定义有 bug / 想加功能 / 改布局 → 新版本
- 已拖入的实例锁定旧版本 → 行为稳定不漂移
- 何时升级、升级到哪 → 显式决策 + 差异可见

### 1.3 核心概念

| 概念 | 说明 |
| :--- | :--- |
| **黑盒引用 (Black-box Reference)** | 复合物料拖入画布后**保留为单一复合节点**，不展开；渲染/出码时按引用解析物料定义。 |
| **materialRef** | `ComponentNode` 上的引用字段：`{ id: string; version: string }`，指向物料定义的具体版本。 |
| **物料版本** | 语义化版本（SemVer），每版本 = 一份 Schema 快照 + 一份 inputs/outputs 契约。 |
| **实例锁定 (Pin)** | 实例总是锁定**具体版本号**（非 semver range），升级是显式操作。 |
| **契约 (Contract)** | 物料的 inputs（注入点声明）与 outputs（事件出口声明）——黑盒模式下才恢复其运行时意义。 |
| **展开实例 / 黑盒实例** | 展开实例 = v2.0 形态（普通子树，无 materialRef）；黑盒实例 = v2.1 形态（带 materialRef）。两种共存。 |
| **草稿 (Draft)** | 物料的未发布编辑态（仅一份，可反复编辑、可丢弃）。发布后才产生不可变版本。 |
| **不可变版本 (Immutable Version)** | 发布产物：发布后永不改写。同一版本 = 同一行为，可复现、可回滚、可 diff。 |
| **契约签名 (Contract Signature)** | inputs/outputs 契约的规范化 JSON 哈希（复用 `shortHash`）。签名不同 = major 的硬标准。 |

## 二、关系模型升级（v2.0 1.4 的扩展）

### 2.1 实例从"转换"变为"引用"

v2.0：定义 ⇄ 实例是**转换**关系（打包产生定义，拖入展开成实例，两向皆"复制"）。

v2.1 黑盒模式：定义 → 实例是**引用**关系（实例保存 `materialRef`，运行时持续解析定义）。

```text
  物料定义(MaterialManifest) ──materialRef {id, version}──► 黑盒实例(ComponentNode)
        │                                                        │
        │ 打包/发新版本（复制语义）                               │ 渲染/出码时解析引用
        ▼                                                        ▼
     定义演进（新版本）                                   实例行为 = 锁定版本的定义
```

### 2.2 目标语义不变（重要）

黑盒复合节点本身是一个**画布实例**（有唯一 id、坐标），因此**可以作为事件动作链的目标**——这补上了 v2.0 展开模式缺失的"物料黑盒可被 reload/开弹窗"语义。目标仍然只认实例 id，规则不变（见 v2.0 1.4.2）。

### 2.3 新旧模式共存

| 维度 | 展开实例（v2.0） | 黑盒实例（v2.1） |
| :--- | :--- | :--- |
| 节点形态 | 子树展开（多节点） | 单一复合节点 |
| materialRef | 无 | 有（id + version） |
| 可编辑粒度 | 直接编辑内部节点 | 编辑实例配置（inputs）+ 定义版本 |
| 版本语义 | 无 | 有 |
| 定义升级影响 | 不影响已拖入实例 | 显式升级后才影响 |
| 出码/渲染 | 走现有原子分支 | 新增 custom-* 解析分支（4.2/4.3） |

**兼容性保证**：v2.0 已生成的展开实例（无 materialRef）照常工作，无需迁移。打包对话框提供"展开物料（默认）vs 黑盒物料"选择。

## 三、版本管理设计（核心）

### 3.1 版本模型

**粒度：每个物料独立版本线**，与另外两层版本正交、互不干扰：

| 版本层 | 载体 | 语义 |
| :--- | :--- | :--- |
| **物料版本**（本版本） | 物料定义文件 | 单个物料自己的演进线 |
| **页面版本** | `PageMeta.version`（v1.3.0 已存在） | 页面整体快照 |
| **平台版本** | 发布版本号 | 平台能力迭代 |

**不可变发布版本（推荐）**：
- 每次**发布**产生一个不可变版本快照，发布后**永不改写**——同一版本 = 同一行为，可复现、可回滚、diff 有意义
- **不是每次更新都发版**：编辑在"草稿"上进行（见 3.2），发布动作才产生新版本，避免版本爆炸

**实例锁定具体版本**：`materialRef.version` 是完整版本号（如 `"1.2.0"`），不引入 semver range 解析——升级永远是显式动作。可选跟随策略见 3.5。

### 3.2 发布流程（草稿 → 不可变版本）

```text
编辑物料（画布重新打包 / 导入 manifest / 直接改契约）──► 草稿态(draft)：仅一份，可反复编辑、可丢弃
                                                              │ 发布（用户确认）
                                                              ▼
                版本号自动判定 ──► 不可变版本快照 + 变更摘要 + 契约签名
                                                              │
                                                              ▼
                            成为新"当前版本"；实例仍锁定旧版，显式升级才跟随
```

**版本号自动判定**：

| 差异特征 | 判定依据 | 建议版本 |
| :--- | :--- | :--- |
| 契约变化（inputs/outputs 增删改） | **契约签名**（规范化哈希）不同 | **major**（需确认"破坏性"） |
| 新增节点 / 新配置 / 新增 outputs | Schema 结构 diff（jsonPatch） | **minor** |
| 仅文案 / 样式 / 布局 / 内部实现 | Schema 结构 diff | **patch** |

- **契约签名**：inputs/outputs 的规范化 JSON 哈希——签名不同 = major 的硬标准，比全量 diff 快且无歧义
- 变更摘要自动生成：`"新增: 头像字段；调整: 卡片标题注入路径"`
- 版本号可手动覆盖；草稿可丢弃（不发版）

### 3.3 版本存储与接口

```
backend/storage/materials/
  custom-user-card/
    manifest.json           # 物料元数据 + 当前版本号 + 版本索引（含契约签名 + 引用计数，不存 schema）
    draft.json              # 草稿：未发布的编辑态（仅一份）
    versions/
      1.0.0.json            # 不可变版本快照（含 schema 快照 + 契约 + 变更摘要 + 发布时间）
      1.1.0.json
```

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/materials/:id/versions` | 版本列表（版本号/发布时间/变更摘要/契约签名/引用数） |
| PUT | `/api/materials/:id/draft` | 保存草稿（编辑态，不产生版本） |
| DELETE | `/api/materials/:id/draft` | 丢弃草稿 |
| POST | `/api/materials/:id/versions` | **发布**：draft → 不可变版本（服务端按 3.2 判定建议版本号，返回版本+摘要） |
| GET | `/api/materials/:id/versions/:v` | 指定版本详情 |
| GET | `/api/materials/:id/versions/:v/diff?base=:b` | 两版本差异（契约层 + 结构层，见 3.6） |
| POST | `/api/materials/:id/rollback` | 回滚：指定历史版本设为当前（保留历史，实例不动） |
| DELETE | `/api/materials/:id/versions/:v` | 归档版本（**当前版本不可删；被实例引用的版本需强确认**，见 3.7） |
| POST | `/api/materials/:id/fork` | **复制新增**：从指定版本快照派生新物料（新 id、可改名，见 3.7） |
| POST | `/api/pages/upgrade-material` | 批量升级：扫描页面，改写引用某物料旧版本的 `materialRef.version` |

- 存储复用 `storageService.ts` 并发写保护；发布/回滚/归档/fork 均写 SQLite 审计
- **引用计数**：由页面扫描得出（黑盒实例带 `materialRef`，可真实统计），存 manifest.json 供保护判断
- **保留策略**：仅保留最近 N 个版本（默认 20，可配置），更老版本自动归档清理；当前版本与被引用版本跳过清理

### 3.4 实例版本锁定与解析

- 黑盒实例节点：`materialRef: { id: 'custom-user-card', version: '1.0.0' }`
- 渲染/出码解析链：`materialRef.id` → 注册表 → 后端取 `versions/<version>.json` → 渲染快照
- 本地缓存：会话内按 `id@version` 缓存已解析快照，避免重复请求
- **缺版本容错**：引用的版本已被归档/删除 → 回退到当前版本并提示；物料整个被删 → 渲染为占位节点并提示（不崩溃）

### 3.5 升级策略（显式、统一、可批量）

| 场景 | 行为 |
| :--- | :--- |
| 物料发布新版本（任意类型） | 物料管理器标记"有新版本"，**不自动升级任何实例** |
| 实例级切换 | **统一"版本切换"入口**：属性面板版本选择器列出全部可用版本（含当前锁定、差异按钮），选择即改 `materialRef.version`——升级与回滚不做 UI 区分，对称简单 |
| 批量升级 | 物料管理器"升级全部实例到 X" → 后端扫描页面批量改写 → 逐页报告结果 |
| major 升级 | 确认框展示契约层 diff + "N 个实例将停留旧版本"；不自动升级任何实例 |
| 回滚 | 同实例级切换（选旧版本）；无数据迁移成本 |

**关键简化**：实例配置（inputs 值、outputs 动作链、布局）与物料定义**分离存储**（前者在页面 Schema，后者在物料版本文件）——升级/回滚只是改一个版本号，**没有数据迁移**。

**可选跟随策略（实例级高级选项，默认关闭）**：
- `pin`（默认）：精确锁定当前版本，任何新发布都不自动生效
- `follow-minor`：解析时取"满足 minor 的最新版本"（patch 自动吃到，major 永不自动）
- `follow-patch`：仅 patch 自动跟随
- 跟随策略在解析层实现（解析器按策略选版本），实例上不存储解析结果

### 3.6 差异对比与审计

- 版本 diff **分两层**：
  - **契约层**：inputs/outputs 签名与内容对比——决定 major、升级确认时展示
  - **结构层**：Schema 快照 JSON Patch 行级对比（新增/删除/修改）——决定 minor/patch、面向用户展示
- 变更摘要自动生成（基于 3.2 判定过程的中间产物）
- 发布/升级/回滚/归档/fork 全部进 SQLite 审计日志（复用现有日志控制器）

### 3.7 引用感知、保护与 fork

**被引用物料是"公共资产"，稳定性由不可变版本保证 + 治理保护兜底：**

| 操作 | 被引用时的行为 |
| :--- | :--- |
| 删除物料 | **阻止** + 展示引用列表（页面名 + 实例数），需强确认才可删除（删除后实例渲染占位，见 4.2） |
| 归档被引用版本 | **阻止** + 提示"N 个实例锁定此版本" |
| 发布破坏性 major | 不阻止，但提示"N 个实例将停留旧版本"（升级是显式动作） |
| 修改物料（发布新版本） | **允许**——不可变版本保证旧版本文件原封不动，被引用行为永不漂移 |

**fork（复制新增）是显式操作，而非强制规则**，用于：
1. 从他人/市场导入的物料，想魔改但不污染原身份
2. 试验性激进分叉（不影响原物料版本线）
3. 原物料被锁定保护时（锁定 = 手动标记，禁止发布 major 或删除，见决策点）

一键"复制为新产品"：新 id、从指定版本快照起步、可改名/改契约，起点版本作为其 `1.0.0`。

### 3.8 导入导出的版本语义（循环带版本）

- `@lowcode-material` 注释块与 `.json` 导出文件**携带版本号**（v2.0 曾移除 version 字段，此处随版本管理恢复）
- 导入时：
  - 平台**已有同 id 物料** → 导入内容进入**草稿**，走发布流程成为新版本，**不覆盖**已有版本与实例锁定
  - 平台**无此物料** → 作为 `1.0.0` 导入
- 效果：自我循环与版本管理自然融合——v1.0.0 导出 → 另一平台导入为 1.0.0 → 改进后导回 → 原平台发布为 1.1.0，实例显式升级

## 四、黑盒引用模式设计

### 4.1 契约：inputs 注入 / outputs 出口

打包为黑盒物料时，自动生成并允许用户编辑的契约：

```ts
interface MaterialContract {
  inputs: Array<{
    name: string;          // 如 "title"
    label: string;         // 如 "标题"
    type: 'string' | 'number' | 'boolean' | 'expression' | 'data';
    path: string;          // 注入点：快照内 JSON 路径，如 "nodes[0].props.title"
    required: boolean;
    default?: unknown;
  }>;
  outputs: Array<{
    name: string;          // 如 "submit"
    label: string;
    nodeId: string;        // 内部事件源节点 id（快照内）
    event: string;         // 事件名，如 "click" / "submit"
  }>;
}
```

- **inputs 默认映射**：打包时自动建议——顶层节点的常用 props（title/placeholder/visible 等）暴露为 input，`path` 指向快照内路径；用户可增删改
- **outputs 默认映射**：快照内所有已配置 `events` 的节点事件自动暴露为 output
- **运行时**：实例配置的 inputs 值在渲染/出码时**注入快照对应路径**；内部节点事件经 output 转发到实例的事件动作链

### 4.2 黑盒渲染（NodeRenderer custom-* 分支）

- `NodeRenderer.vue` 新增分支：`node.materialRef` 存在时 → 解析物料快照 → **注入实例 inputs 配置** → 递归渲染快照子树（复用现有嵌套渲染）
- 解析失败（物料被删/版本缺失）→ 渲染占位节点 + 提示，不崩溃
- 画布上黑盒节点与普通节点外观区分（物料图标 + 角标显示版本号）

### 4.3 黑盒出码（codeGenerator custom-* 分支）

- `renderNodeMarkup` 新增 case：`node.materialRef` → 解析快照 → 注入 inputs → **递归展开出码子树**（复用现有 `renderNodeToTemplate` 递归）
- 实例的事件动作链（绑定在 output 上）正常生成

### 4.4 属性面板

- 黑盒实例的抽屉显示：
  - **inputs 配置表单**：按契约渲染输入控件，值存实例节点
  - **outputs 绑定**：每个 output 一个事件编辑器（复用现有动作链编辑）
  - **版本区**：当前锁定版本、可升级版本入口、查看 diff
  - **内部编辑**：进入"编辑物料定义"模式（从画布重新打包并发布为新版本）

### 4.5 打包对话框扩展

- 新增"物料形态"选择：**展开物料（v2.0 默认）/ 黑盒物料（v2.1）**
- 选黑盒时：显示自动生成的契约（inputs 映射 / outputs 出口），可编辑后确认
- 选展开时：与 v2.0 完全一致

## 六、里程碑拆分

### M1 — 黑盒引用 + 契约

**交付**：
1. shared 类型：`materialRef` / `MaterialContract`（inputs 映射 / outputs 出口）
2. `NodeRenderer` custom-* 分支：快照解析 + inputs 注入 + 递归渲染 + 占位容错
3. `codeGenerator` custom-* 分支：快照展开出码 + inputs 注入
4. 打包对话框"黑盒物料"选项 + 契约自动生成/编辑
5. 属性面板 inputs 表单 / outputs 绑定 / 版本区（只读显示）

**验收**：
- 黑盒物料拖入 → 画布渲染正确（inputs 值生效），出码与"展开模式出码"语义等价
- 输出事件绑定动作链可执行；解析失败渲染占位不崩溃
- 展开实例（v2.0）不受影响

### M2 — 版本管理（发布 / 锁定 / 升级 / 回滚）

**交付**：
1. 版本存储结构（含 draft）与 `/api/materials/:id/versions` 全组端点（diff / rollback / archive / fork / draft）
2. 版本号自动判定（契约签名 + schema diff → major/minor/patch 建议）
3. `materialRef` 锁定解析 + 会话缓存 + 缺版本容错
4. 升级：实例级版本切换（属性面板）+ 批量（`/api/pages/upgrade-material`）+ 可选跟随策略
5. 版本对比视图（契约层 + 结构层）+ 变更摘要
6. 引用计数（页面扫描）+ 删除/归档保护 + fork
7. 审计全覆盖

**验收**：
- 发布 patch → 实例不自动变；实例显式升级 → 行为更新；回滚 → 实例降回（无数据迁移断言测试）
- major 升级有契约 diff 确认；批量升级逐页报告
- 版本文件损坏/删除 → 容错回退当前版本，页面不崩溃

### M3 — 治理与收尾

**交付**：
1. 物料管理器版本面板（历史列表/对比/回滚/归档/批量升级/fork/引用统计）

## 七、风险与决策点

| 决策点 | 本版本选择 | 理由 | 备选 |
| :--- | :--- | :--- | :--- |
| 版本粒度 | **每物料独立版本线** | 演进节奏互不拖累，与页面/平台版本三正交 | 平台级统一版本（v3.0 若需） |
| 更新策略 | **草稿 + 不可变发布版本** | 避免版本爆炸；行为可复现、可回滚、diff 有意义 | 单可变版本直接覆盖（弃——实例行为漂移） |
| 实例版本锁定 | **默认 `pin` 具体版本号**（可选 follow-minor/patch） | 显式可控，同时给自动化留口 | 强制 semver range（复杂度高） |
| 升级是否自动 | **全部显式**（实例级切换 + 批量级） | 避免隐式行为漂移 | 全局默认 follow（后续可配） |
| **被引用物料修改策略** | **原地发布不可变版本 + 引用保护**（不强制 fork） | 不可变版本已保证被引用行为永不漂移；保留原地演进/批量升级能力 | 强制 fork（弃——升级路径断裂、变体爆炸） |
| fork 语义 | **显式操作**（复制新增），用于魔改/激进分叉/锁定保护 | 需要时可用，不强制 | — |
| 升级/回滚数据迁移 | **无迁移**（实例配置与定义分离存储） | 升级只改 version 号，成本趋零 | — |
| major 升级 | 需要契约 diff 确认 + 引用影响提示 | 破坏性变更必须可见 | — |
| 契约注入路径 | 打包时自动建议 + 用户可编辑 | 默认可用，复杂场景可手调 | 可视化路径选择器（后续） |
| inputs/outputs 契约 | 仅黑盒模式启用 | 展开模式无运行时意义（v2.0 已论证） | — |
| 版本存储 | `materials/<id>/versions/<v>.json` | 每版本独立文件，diff/回滚/归档天然支持 | SQLite 版本表（v3.0 若规模变大） |

**风险清单**：
- **悬空 materialRef**（物料被删/版本归档）→ 渲染占位 + 回退当前版本 + 提示（4.2/3.4 容错）
- **批量升级误改** → 后端逐页报告 + 升级前整体 diff 预览 + 审计可回滚
- **注入路径失效**（新版本快照结构调整，旧 inputs path 失效）→ 版本发布时校验 path 合法性；升级时检测失效 path 并提示
- **版本膨胀** → 保留策略（最近 N 版）+ 当前版本与被引用版本不可清理
- **引用计数不一致**（页面扫描与并发保存竞态）→ 引用计数存 manifest.json 但以"删除/归档前实时扫描复核"为准，计数只作提示不硬拦
- **循环引用（黑盒）** → 黑盒物料定义内不允许引用自身（发布时校验）；嵌套黑盒允许但深度限制沿用 v2.0
- **fork 失控扩张**（变体爆炸）→ fork 保留但物料管理器按"来源物料"分组展示；真不需要历史时可删除 fork

## 八、演进路线（v2.1.0 之后）

```text
v2.1.0 黑盒引用+版本管理        v2.2.0 物料生态
┌────────────────────┐    ┌────────────────────┐
│ 黑盒引用/契约       │    │ 物料市场/分享      │
│ 版本发布/锁定/升级  │ →  │ 远程物料 SDK       │
│ 回滚/差异对比       │    │ (defineMaterial)  │
│ 批量升级/审计       │    │ 协同/权限治理      │
└────────────────────┘    └────────────────────┘
```

- v2.1 之后的候选增强：semver range 可选、自动跟随 minor/patch、可视化注入路径选择器、物料订阅通知
