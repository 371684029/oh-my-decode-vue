# 低代码前端可视化平台 (Low-Code Studio) - v1.3.0 数据驱动能力与体验加固规划

> **版本定位**：数据驱动能力 (Data-Driven Capabilities) + 体验与工程配套加固
> **状态**：规划中 (Planned)
> **前置版本**：v1.2.0（多图层架构与生命周期）
> **平台定位约束**：纯前端搭建 + 出码，**不生成后端代码**；数据能力指前端运行时接入并绑定数据，出码产物通过 `fetch` 对接已有/任意 REST API。

---

## 一、核心目标（数据驱动三层）

当前平台能"搭界面"但组件数据全部来自硬编码 mock，页面不具备真实数据能力。v1.3.0 落地前端"数据接入层"：

1. **L1 - 表达式绑定真实渲染**：`{{ }}` 表达式从"属性面板预览"升级为**画布组件真实求值**；出码时内联 `schema.state`。
2. **L2 - 接口数据源绑定 (DataSource)**：节点配置 `apiBinding`（URL/方法/参数/响应路径提取/自动请求），设计器内实时预览真实数据，出码产物生成**前端** `fetch` 调用。
3. **L3 - 事件动作链最小闭环 (Action Chain)**：`click` 事件编排动作链（刷新数据/弹窗注入/Loading/消息/状态更新），页面从"展示"变"可交互"。

> 对齐 `docs/COMPONENT_API_EVENT_MAPPING.md` 的 CAE 契约，取其**最小可行子集**；GraphQL / 完整管道编排 / `functions` 业务脚本留待后续。

## 二、配套能力与工程优化（全量 P0/P1/P2 纳入）

### 🔴 P0 —— 决定平台价值上限

**P0-1 真实数据源绑定** → 即上文 L2（核心交付，必做）。

**P0-2 UI 端到端测试（Playwright TS 化并入 CI）**
- 现状：`verify_v120.py` 为 Python 遗留脚本，无断言、未纳入 CI
- 方案：迁移为 `frontend/e2e/` + Playwright（TS），断言核心交互闭环：拖入物料 → 改属性 → 保存 → 载入 → 出码
- 验收：`npm run test:e2e` 在 CI 中通过；关键路径有断言

**P0-3 图层 children 编辑（图层内拖放组件）**
- 现状：图层 `children` 类型有定义但 UI 无法编辑
- 方案：设计器支持"进入图层"编辑——选中 dialog/自定义图层后，画布切换为该图层，可拖入/摆放组件；渲染时图层内组件随图层渲染
- 验收：弹窗图层可放入表单/表格并随弹窗渲染

### 🟡 P1 —— 体验与可信度

**P1-1 出码数据参数化**
- 现状：ProTable/ProForm 数据为生成器内硬编码 mock
- 方案：`apiBinding` 存在 → 生成真实 fetch；无 → 保留 mock 但注释"占位数据，可在设计器配置数据源替换"
- 验收：出码产物不再有无标注的硬编码数据

**P1-2 后端认证最小化**
- 现状：`operator` 取自可伪造的 `x-operator` header，无任何鉴权
- 方案：`X-Api-Key` 校验（环境变量配置，可关闭）+ operator 改为服务端从请求解析
- 验收：无/错误 Api-Key 请求被拒（401）；配置关闭时保持向后兼容

**P1-3 历史栈优化（结构化 diff）**
- 现状：30 步全量 `JSON.stringify` 快照，内存/序列化开销随 schema 线性增长
- 方案：改为**增量快照**——记录操作逆操作或 RFC 6902 JSON Patch（docs/0.2.0_OPTIMIZATIONS.md 已有规划）
- 验收：大 schema 下撤销/重做内存占用显著下降；行为兼容现有 30 步语义

**P1-4 Schema 版本化与回滚**
- 现状：`meta.version` 静态存在，保存不递增；审计日志只有快照摘要
- 方案：保存时自动递增 `meta.version`；审计日志记录前后版本 diff；后端提供"按版本回滚"接口（读取备份链恢复）
- 验收：连续保存后版本递增；可回滚到指定历史版本

### 🟢 P2 —— 打磨细节

**P2-1 嵌套容器真实化**
- 现状：`pro-container` 占位渲染"Slot 占位区域"，`children` 不参与渲染
- 方案：递归渲染 `children`，支持向容器内拖入子节点；出码递归生成嵌套结构
- 验收：容器内可放按钮/卡片并随容器布局渲染

**P2-2 备份轮转 + 恢复接口**
- 现状：单份 `.bak` 覆盖式备份
- 方案：保留最近 N 份（`{id}.bak.{n}`），新增 `GET /api/schemas/:id/backups` 与 `POST /api/schemas/:id/restore` 恢复接口
- 验收：多代备份可查可恢复

**P2-3 并发写保护**
- 现状：`storageService` 临时文件用 `Date.now()` 命名，同 id 并发写有竞态
- 方案：按 id 串行化写队列/锁
- 验收：并发保存同 id 不产生损坏文件

**P2-4 导出代码质量**
- 现状：生成代码注释中文化混排、缩进偶有错位、展示无高亮
- 方案：生成代码统一规范（注释/缩进），CodeExportDialog 代码块加语法高亮（highlight.js）
- 验收：三种产物体感接近手写代码

**P2-5 文档重构（docs 分区）**
- 现状：docs 16 份混排"已实现规范"与"规划蓝图"，与代码比例失衡
- 方案：目录重组为 `docs/implemented/`（JSON 契约/物料规范/CAE 规范）与 `docs/roadmap/`（各版本计划），README 索引同步
- 验收：README 文档索引按分区引用；不再误读规划为已实现

**P2-6 错误降级与全局提示**
- 现状：后端不可达仅 console 报错，无用户可见提示；axios 无统一拦截
- 方案：axios 统一拦截器 + 全局 ElMessage 提示；设计器保存/载入失败可重试
- 验收：后端宕机时 UI 有明确提示且操作不静默失败

## 📋 Schema 契约扩展

在 `ComponentNode`（shared 包）上**非破坏性扩展**（缺省保持原行为）：

```ts
export interface ComponentNode {
  // ... 既有字段不变 ...

  // L2: 接口数据源绑定（缺省 = 不请求，沿用 mock）
  apiBinding?: {
    url: string;                       // 接口地址（支持 {{ }} 表达式）
    method?: 'GET' | 'POST';           // 默认 GET
    params?: Record<string, any>;      // 请求参数（值支持 {{ }} 表达式求值）
    autoFetch?: boolean;               // 挂载时自动请求，默认 true
    responsePath?: string;             // 数据列表提取路径（如 "data.list"）
    totalProp?: string;                // 分页总数提取路径（如 "data.total"）
  };

  // L3: 事件动作链（原 events 占位空对象 → 真实事件规则）
  events?: Record<string, EventRule>;
}

/** 事件规则：监听某事件并按序执行动作链 */
export interface EventRule {
  enabled: boolean;
  actions: ActionNode[];
}

/** 动作节点：最小可行动作集 */
export interface ActionNode {
  id: string;
  type:
    | 'reload_data'      // 刷新目标节点数据（如表格 reload）
    | 'open_dialog'      // 打开指定图层弹窗（可携带行数据 payload）
    | 'close_dialog'     // 关闭指定图层弹窗
    | 'toggle_loading'   // 显示/隐藏 Loading 图层
    | 'show_message'     // 消息提示
    | 'set_state';       // 更新页面 state（联动表达式绑定）
  target?: string;       // 目标节点 id 或图层 id
  payload?: Record<string, any>;
}

// P1-4: PageSchema.meta 补充（版本化）
meta: {
  author: string;
  description: string;
  version: string;          // 保存时自动递增（如 1.0.0 → 1.0.1）
  prevVersion?: string;     // 记录上一版本号，供回滚
};
```

### 示例：按钮点击 → 携带行数据打开详情弹窗

```json
{
  "id": "btn_view_detail",
  "type": "el-button",
  "props": { "text": "查看详情" },
  "events": {
    "click": {
      "enabled": true,
      "actions": [
        { "id": "a1", "type": "set_state", "payload": { "currentRow": "$event.row" } },
        { "id": "a2", "type": "open_dialog", "target": "layer_dlg", "payload": { "bindState": "currentRow" } }
      ]
    }
  }
}
```

### 示例：ProTable 绑定分页接口

```json
{
  "id": "tbl_users",
  "type": "pro-table",
  "apiBinding": {
    "url": "/api/users",
    "method": "GET",
    "params": { "page": "{{ state.page }}", "size": 10 },
    "autoFetch": true,
    "responsePath": "data.list",
    "totalProp": "data.total"
  }
}
```

## 🧩 设计器 UI 扩展

属性抽屉在既有 4 Tab 基础上新增 2 Tab（对齐 CAE UX 规范），并补充图层编辑：

| Tab | 内容 |
|---|---|

| **事件** | 为 `click` 编排动作链：添加/排序/删除动作，配置 target/payload |
| **图层内编辑**（P0-3） | 选中 dialog/自定义图层时，画布切换为该图层内容，可拖入组件 |

## ⚙️ 前端运行时实现

1. **`frontend/src/utils/dataSource.ts`（新）**：`ApiExecutor` 统一请求层
   - `fetchWithParams(node)`：对 `params`/`url` 中 `{{ }}` 用受限求值器求值
   - `extractByPath(resp, path)`：点路径/JSONPath 子集提取
   - 统一错误处理（不可达 → ElMessage + 状态复位）
   - `reload(node)` / `openDialog` / `closeDialog` / `toggleLoading` 动作执行器
2. **ProTable / ProForm 接入**：`onMounted` 按 `autoFetch` 请求并注入数据；暴露 `reload()`；分页 `total` 用 `totalProp`
3. **事件接线**：组件 `@click` → 按 `node.events.click.actions` 顺序执行动作链

---

## 🔨 出码引擎升级（纯前端产物）

- 有 `apiBinding` → 生成真实 `fetch` 代码（含 `responsePath` 提取、分页、错误处理），**不再硬编码 mock**
- 无 `apiBinding` → 保留 mock 但注释"占位数据，可配置数据源替换"（P1-1）
- `events` → 生成事件 handler（`handleRowAction` → `reloadData('tbl_users')` / `openDialog(...)`）
- `pro-container` 递归渲染 children（P2-1）；生成代码规范统一（P2-4）
