# 低代码前端可视化平台 (Low-Code Studio) - v1.7.0 条件交互规划

> **版本定位**：让已经能出码的页面按条件显示、按条件执行动作，并在提交前拦住空的必填项
> **状态**：已实现 (Implemented)。范围与验收见下文，实现已合入 v1.7.0
> **前置版本**：v1.6.0（出码正确性、设计器与导出一致、存储队列、审计补丁）
> **平台定位约束**：纯前端搭建 + 出码，**不生成后端代码**。数据请求仍由浏览器 `fetch` 访问已有 REST API

---

## 一、为什么做这一版

v1.6.0 把出码、占位数据、分页、弹窗载荷和存储竞态收口了。页面可以拖出来、导出后能跑，但业务页面还缺三件每天都会用到的事：

- 表单项上的「必填」只画出星号。设计器里的表单没有提交按钮；导出的 `handleSubmit` 无论字段是否为空都提示成功。
- 显隐和分支只能靠手写完整动作链，动作不能按条件跳过，组件也不能按 `state` 显示或隐藏。
- `pageSchema.state` 已经参与表达式和分页，出码也会写成 `reactive({...})`，设计器里没有地方编辑初始值。

v1.7.0 把这三件事做成设计器和导出同一套规则。节点式流程图、管道编排和主题系统仍不在本版，原因见文末范围边界。

---

## 二、P0 — 表单提交前校验必填

**现状**：`pro-form` 的表单项有 `required` 开关，`ProForm.vue` 把它传给 `el-form-item` 的星号，没有校验函数，也没有提交按钮。`codeGenerator` 的 `handleSubmit` 取到表单后直接 `ElMessage.success('表单提交成功')`。

**方案**：

- 抽出纯函数 `emptyRequiredFields(items, values)`。只检查 `component` 为 `input`、`select`、`date` 且 `required === true` 的项。值为 `null`、`undefined` 或去掉首尾空白后的空字符串时算未填。`switch` 忽略 `required`，`false` 是合法值。
- 设计器表单补上与出码一致的「提交」「重置」。提交时先跑上述函数；有未填项时在对应表单项下显示「请填写{label}」，不提示成功。全部通过后提示成功。
- 若该表单节点配置了 `events.submit` 且 `enabled`，校验通过后按现有 `executeActions` 执行；校验失败不执行。出码的 `handleSubmit` 使用同一规则：先判断空必填，失败则 `ElMessage.warning` 并 `return`；通过后再执行 `submit` 动作链，然后提示成功。
- 重置清空当前表单字段，并清掉未填提示。重置不跑 `submit` 动作链。

**验收**：两个必填输入框，只填一个就提交时，设计器和导出页面都停在原处并指出未填项。两项都填上之后，导出的 `handleSubmit` 才会执行 `submit` 动作。开关即使标了必填也不拦截。

## 三、P0 — 按表达式显隐

**现状**：`{{ }}` 可以绑到按钮文字等属性上，组件本身不能按 `state` 显示或隐藏。画布上的节点一直占着网格。

**方案**：

- `ComponentNode` 增加可选字段 `visibleWhen?: string`。空字符串或未填表示始终显示。
- 值必须是整段 `{{ expr }}`，并且现有 `canInlineExpression` 返回真。求值沿用 `parseExpression`，结果用 JavaScript 真值判断。
- 设计器用 `v-show` 隐藏不满足的节点，网格占位保留，避免拖拽坐标乱跳。属性抽屉里可以编辑该字段；表达式不合法时节点保持显示，并在抽屉给出警告，不把原文拼进出码。
- 合法表达式在 SFC 与 HTML 模板上输出 `v-show="expr"`。设计器与出码对同一 `state` 得到同一显隐结果。

**验收**：`visibleWhen` 为 `{{ state.show === true }}` 且初始 `state.show` 为 `false` 时，设计器画布和导出页面都看不到该节点；把 `state.show` 设为 `true` 后两者都显示。`{{ 1) || alert(1) || (1 }}` 不产生 `v-show`，节点保持显示。

## 四、P0 — 动作按条件跳过

**现状**：`ActionNode` 只有 `type`、`target`、`payload`。动作链一旦开始就按顺序全执行。

**方案**：

- `ActionNode` 增加可选 `when?: string`，规则与 `visibleWhen` 相同：整段 `{{ expr }}` 且通过 `canInlineExpression`。
- 设计器 `executeAction` 在动作开始前求值。结果为假则跳过这一条，继续下一条。未填 `when` 的动作保持现在的行为。
- 表达式不合法时跳过该动作，并在属性抽屉标出警告。出码不把原文写进 `if`。
- 合法表达式在 SFC 与 HTML 里包一层 `if (expr) { ... }`，包住这一条动作现有的语句。`open_dialog` 的载荷赋值也在这个 `if` 里面。

**验收**：同一条 `click` 链上，第一条 `when` 为 `{{ state.ok === true }}` 的 `show_message`，第二条没有 `when`。`state.ok` 为 `false` 时只执行第二条；为 `true` 时两条都执行。设计器与导出页面一致。

## 五、P0 — 页面初始状态可编辑

**现状**：分页把 `state.page` 写进 schema，表达式读取 `pageSchema.state`，出码把 `state` 对象字面量写进 `reactive`。设计器没有页面级编辑入口，作者无法声明 `show`、`role` 这类初始值。

**方案**：

- 在物料面板增加「页面状态」页。列出 `pageSchema.state` 的键和 JSON 值，可增删改。
- 键名只允许 `[A-Za-z_][A-Za-z0-9_]*`，并拒绝现有 `FORBIDDEN_STATE_KEYS`（`__proto__`、`prototype`、`constructor`）。值用 `JSON.parse` 接受字符串、数字、布尔、`null`、对象和数组。解析失败时不写入，输入框保留原文并提示。
- 保存进 `pageSchema.state` 后，画布上的 `visibleWhen`、动作 `when` 和已有 `{{ }}` 立刻按新值求值。
- 出码继续使用这份对象。不要在生成代码里用 `Object.assign` 把用户键铺进原型链；沿用 v1.6.0 的按键赋值。
- 分页写入的 `state.page` 仍保留。打开面板再保存时，不得丢掉未在表格里改过的已有键。

**验收**：新增 `show: false` 后，依赖它的显隐立即生效，导出的 `reactive` 初始值包含 `"show": false`。键名 `__proto__` 不能加入列表。

## 六、测试

每一项都要有自动测试。

| 项 | 测试 |
|---|---|
| 必填校验 | `emptyRequiredFields`：空字符串、空白、`null` 算未填；`false` 的开关不算未填 |
| 设计器提交 | 表单只填一半时不出现成功提示，也不跑 `submit` 动作；填完后动作执行 |
| 出码提交 | SFC 与 HTML 的 `handleSubmit` 在必填为空时 `return`，不为空时执行 `submit` 动作 |
| 显隐 | 合法 `visibleWhen` 生成 `v-show`；非法表达式不生成 `v-show` |
| 动作条件 | `when` 为假时跳过该动作；下一条仍执行。非法 `when` 不出现在生成脚本里 |
| 页面状态 | 合法键写入 schema 并出现在出码初始值；禁止键被拒绝 |

E2E 增加一条：页面状态里把 `show` 设为 `false`，按钮 `visibleWhen` 指向它，画布上看不到该按钮；改成 `true` 后按钮出现。后端不可用时这条用例跳过。现有「保存并写入 JSON」仍要求后端。

## 八、范围边界（本版明确不做）

- 不实现 `docs/implemented/PIPELINE_ORCHESTRATION.md` 的 `beforeTransform` / `scriptTransform` / `afterTransform`，也不做节点连线式逻辑图。`docs/roadmap/0.4.0_PLAN.md` 里的流程图编辑器仍留在那份远期草稿。
- 不做正则规则生成器、主题换肤、国际化字典、Mock 服务和远程物料。
- 不做 GraphQL、WebSocket、页面路由跳转。
- 不生成后端代码，不引入 RBAC / SSO，不把 `VITE_API_KEY` 改成用户登录。
- 不改 v1.6.0 已定的请求地址策略：本机和私网数据源仍然允许，元数据地址和重定向复核保持原样。
