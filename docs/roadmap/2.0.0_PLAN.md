# v2.0.0 自我循环物料机制规划 (Self-Recycling Material Loop)

> **文档定位**：v2.0.0 版本规划 —— 让"用户拖拉拽生成的组件"可以重新导入为物料，形成自我循环生成机制。
> **状态**：规划中 (Draft / 待评审)
> **前置版本**：v1.12.0（已合入 `main`）

---

## 一、目标与定义

### 1.1 一句话目标

**任何用户在画布上通过拖拉拽 + 配置生成的组件（含组件组合、事件动作链、数据源绑定），都能一键打包为"自定义物料"；该物料可再次被拖拽使用、再次出码导出、再次导入注册——形成无限自我循环。**

### 1.2 自我循环 (Self-Recycling Loop)

```text
        ┌────────────────────────────────────────────────────────────┐
        │                                                              │
        ▼                                                              │
   ┌──────────┐   拖拽/配置   ┌────────────┐   选中打包   ┌───────────────┐
   │  物料面板  │ ──────────► │  画布组件节点  │ ──────────► │ 复合物料 Manifest │
   │ (含自定义) │             │ (JSON Schema)│             │ (schema 快照)    │
   └──────────┘              └────────────┘             └───────┬───────┘
        ▲                                                       │ 自描述出码
        │                                                       ▼
        │  注册入库                                    ┌─────────────────┐
        └────────────────────────────────────────────── │ 导出代码 (.vue/.html)  │
                    导入管道 ← 解析 ←──────────────────  │ 内嵌 @lowcode-material  │
                 (manifest 注释块)                       └─────────────────┘
```

**循环不变量的定义**：一份 Schema 快照 → 打包为物料 → 拖入展开为 Schema 快照，二者在结构上等价（除 id 重写外），使"导出 → 导入 → 导出"在语义上幂等。

### 1.3 核心概念

| 概念 | 说明 |
| :--- | :--- |
| **复合物料 (Composite Material)** | 由用户从画布选中节点组打包生成的物料。本质是 `MaterialItem` 描述 + 一份 Schema 快照（`ComponentNode[]`）。 |
| **原子物料 (Atomic Material)** | 现有内置物料（pro-table、pro-form、el-* 等），静态注册，不可变。 |
| **物料 Manifest** | 物料的完整描述符：继承 `MaterialItem`，追加 `kind/schema/summary` 等元数据。 |
| **自描述出码 (Self-describing Codegen)** | 导出复合物料时，把 Manifest（含 Schema 快照）以 `@lowcode-material` 注释块嵌入生成代码头部。导出文件 = 可运行代码 + 可导入物料定义。 |
| **运行时物料注册表 (Runtime Registry)** | 内置物料维持静态注册（快路径），用户物料运行时注册/注销，持久化到后端。 |

### 1.4 四者关系模型（物料定义 / 节点实例 / 目标 / 图层）

循环机制建立前，必须精确界定四个概念及其转换关系。**核心原则：目标只认"实例"，不认"定义"。**

#### 1.4.1 形式化定义

| 概念 | 类型 | 特征 |
| :--- | :--- | :--- |
| **物料定义** | `MaterialManifest` | 静态模板：有 `type`、**无实例 `id`**、无坐标、无运行时状态。驻留注册表 / 后端存储 / 导出文件。 |
| **节点实例** | `ComponentNode` | 动态实体：物料拖入画布后生成，有唯一 `id`、坐标、props 值、运行状态。 |
| **目标** | `NodeId \| LayerId`（`ActionNode.target`） | 引用：事件动作链指向的**实例 id 或图层 id**，运行时经 `getNode(id)` / `getLayer(id)` 解析。 |
| **图层** | `LayerConfig` | 页面级结构（dialog / loading / custom-html）：有 `visible/zIndex` 运行时状态，**不是物料**，不参与拖拽。 |

#### 1.4.2 转换关系与三条命题的精确化

```text
              拖入实例化 (instantiate, 产生新 id)             打包 (package, 复制语义)
  物料定义(MaterialManifest) ◄───────────────────────────────────────► 节点实例组(ComponentNode[])
        │                                                                │
        │ 无 id / 无状态 / 无坐标                                        │ 有 id / 有状态 / 有坐标
        ▼                                                                ▼
   不能直接作目标                                                  可作为目标 (target = 实例 id)
        ▲                                                                │
        └────── 拖入后产生新实例(新 id) ─────────────────────────────────┘
```

用户三条命题的精确表述：

1. **"物料可以成为目标"** → 精确：物料**拖入实例化后**（成为节点实例）可以作为目标。物料定义本身不能——目标解析只接受实例 id。
2. **"目标也可以成为物料"** → 精确：作为目标的**节点实例（连同其子树）**可以打包成物料。打包时目标引用按 1.4.3 规则处理。
3. **"打包之后的物料不能再成为目标" → 对**。原因：打包产物是"定义"，无实例 id，目标解析必然失败。但打包是**复制语义**——原画布实例仍在、仍可作目标；打包只是"额外生成一个可复用定义"，不剥夺原实例的目标资格。

#### 1.4.3 目标引用打包规则（防止悬空）

打包时对子树内所有 `ActionNode.target` 分类处理：

| 目标解析结果 | 处理 |
| :--- | :--- |
| 指向**子树内**节点 id | 保留相对引用，实例化时 `rewriteTargets` 重写为新 id |
| 指向**子树外**节点 id | 告警 + 默认剥离该动作（打包对话框列出，用户可确认） |
| 指向**图层** id（dialog / loading） | 告警 + 默认剥离该动作（物料不封装图层） |
| 无 target（`show_message` 等）或 target 为 state | 原样保留 |

**容错不变式**：实例化后 `rewriteTargets` 解析不到的 target 置空，现有 `executeActions` 在 `getNode` 返回 undefined 时安全跳过——任何打包产物拖入后永不报错。

#### 1.4.4 循环不变式

```text
instantiate(package(nodes)) ≅ nodes    // 打包→实例化：子树结构等价（仅 id/坐标不同）
```

这是闭环正确性的核心断言，作为 M1/M2 的回归测试基线。**展开模式下实例不引用定义**：改物料只是改模板，不影响任何已拖入实例——因此本版本无版本语义（版本管理归 v2.1 黑盒引用模式，见第七节决策点）。

## 三、闭环机制设计

### 3.1 复合物料定义（shared 类型扩展）

```ts
// shared/src/index.ts 新增
export type MaterialKind = 'atomic' | 'composite';

export interface MaterialManifest extends MaterialItem {
  kind: MaterialKind;              // atomic = 内置；composite = 用户生成
  /** 复合物料的核心：画布节点子树快照（拖入时展开实例化） */
  schema?: ComponentNode[];
  /** 包含组件类型清单（展示用，非契约）：如 ["pro-table", "el-button"] */
  summary?: string[];
}
// 注意：无 version / origin / createdAt —— 展开模式下物料是纯模板，
// 无版本与引用语义；这些元数据留给 v2.1 黑盒引用模式。
```

### 3.2 运行时物料注册表（frontend）

- 新增 `frontend/src/registry/materialRegistry.ts`：
  - 内置种子：直接引用现有 `MATERIAL_REGISTRY`（`kind: 'atomic'`，只读）
  - 动态区：`Map<string, MaterialManifest>` 存用户物料，提供 `register / unregister / list / get / has`
  - 命名空间隔离：用户物料 type 强制 `custom-` 前缀，与内置类型（`pro-*`/`el-*`）物理隔离，杜绝覆盖
- `MaterialList.vue` 新增「自定义物料」tab，数据源从注册表动态取（当前 `proMaterials`/`elementMaterials` 两个 computed 保持内置来源）

### 3.3 统一动作模型：manifest 是唯一中间表示

整个循环只有四种转换，全部围绕 manifest：

```text
       序列化(构造)              编码(文件化)
画布节点树 ──────────► MaterialManifest ──────────► 文件(.vue/.html/.json)
     ▲                        │    ▲
     │     实例化(展开)        │    │    解码(解析)
     └────────────────────────┘    └──────────────────► 导入
```

| 动作 | 方向 | 本质 |
| :--- | :--- | :--- |
| 另存为物料（打包） | 画布节点树 → manifest | 序列化：构造物料定义 |
| 导出 | manifest → 文件 | 编码：manifest 写成自描述文件 |
| 导入 | 文件 → manifest | 解码：解析回物料定义 |
| 拖入 | manifest → 画布节点树 | 实例化：展开为子树 |

**关键结论**：导出 = 打包 + 编码，一个入口的两个产物。不存在"不需要打包"的导出——因为导出文件要可再导入，必须携带物料元信息 + Schema 快照（即 manifest），否则只是"页面代码"而不是"物料"。用户感知上是一个动作：「另存为物料」对话框里勾选"同时下载导出文件"，内部透明完成注册与编码。

### 3.3.1 映射规则（画布节点树 → MaterialManifest）

| manifest 字段 | 映射来源 |
| :--- | :--- |
| `type` | `custom-` + 用户名称 slug（小写连字符） |
| `label` / `icon` / `category` | 用户填写（默认取选中节点组顶层节点 label） |
| `defaultLayout.w/h` | 节点组**外接包围盒**：`w = max(x+w) − min(x)`，`h = max(y+h) − min(y)` |
| `defaultProps/Attrs/Config` | 空对象（复合物料的"配置"就是子树本身，不另设默认值） |
| `summary` | 遍历子树聚合的**组件类型清单**（展示用，如 `["pro-table","el-button"]`），非契约 |
| `schema` | 扁平化后的子树快照（核心字段） |

三个容易漏的细节：

1. **坐标归一化**：打包时所有节点 `layout.x/y` 减去包围盒左上角 `(minX, minY)`，存相对布局；拖入时整体平移到落点。否则物料在不同位置拖入会错位。
2. **id 策略**：打包时**保留原 id 作种子**（打包零成本、零重写）；拖入实例化时才 `assignIds` 重写。事件动作链 `target` 引用同理——打包保留相对引用，实例化时 `rewriteTargets`。
3. **扁平化**：子树里若含其他复合物料，递归展开为原子节点（visited 防环 + 深度上限 5）。保证 `schema` 永远是纯原子节点——拖入后渲染/出码零特殊分支。

### 3.4 拖入实例化（物料 → 画布）

- 复用 `pasteNode()` 的 `assignIds` + `rewriteTargets`，新增 `designerStore.addCompositeFromMaterial(manifest, dropX, dropY)`：
  1. 深拷贝 `manifest.schema`
  2. 按落点平移全部节点坐标（`x += dropX − minX`，`y += dropY − minY`）
  3. `assignIds` 重写全部子孙 id（保持 `custom-*` type 不变）
  4. `rewriteTargets` 重写事件动作链里的子树内 `target` 引用（图层/子树外引用已在打包时剥离，见 1.4.3；解析不到的 target 置空，执行时安全跳过）
  5. 整体 push 进 `activeChildren`，全量重算网格布局
- 结果：画布上出现的是一棵**普通节点子树**，渲染、编辑、出码全部走现有路径，无需新增 `NodeRenderer` 分支、无需新增出码分支

### 3.5 自描述出码（manifest → 文件）

- `codeGenerator.ts` 新增 `generateMaterialBundle(manifest): { vue: string; html: string }`：
  - 构造一个临时 `PageSchema`（`children = manifest.schema`，`type: 'component'`）
  - 复用 `generateVueSFC` / `generateHTML` 生成主体
  - 在产物头部**内嵌 manifest 注释块**（导出文件的"物料身份"）：

```vue
<!-- @lowcode-material
{"type":"custom-user-card","kind":"composite",
 "label":"用户卡片","icon":"Avatar","category":"pro",
 "summary":["pro-table","el-button"],
 "schema":[...归一化后的节点快照...]}
-->
```

- 同一 manifest 也可导出为纯 `.json`（仅 manifest，不含代码），供用户间交换

### 3.6 导入管道（文件 → manifest）

- 新增 `frontend/src/utils/materialImport.ts`，入口为「物料管理器」的文件选择/粘贴：
  1. **类型分派**：`.json` → 直接解析为 `MaterialManifest`（Zod 校验）；`.vue` / `.html` / `.js` → 走注释块提取
  2. **注释块提取（首选）**：正则定位 `@lowcode-material` 块 → `JSON.parse` → Zod 校验 → 若含 `schema` 快照则**零猜测还原**
  3. **启发式降级（无注释块）**：仅提取 title/script 中的 props 线索，产物标记为 `kind: 'composite'` 但 **`schema: []`（空快照）** → 注册成功但拖入时提示「该物料无可渲染内容，请编辑其定义」——避免平台对第三方代码做不可靠的"读懂"承诺
  4. **安全闸门**：所有源码字段经 DOMPurify 消毒 + 长度上限（复用现有 Zod 约束）；manifest 字段经现有 `schemaValidation` 强校验
- 导入成功后：注册进运行时注册表 + `POST /api/materials` 持久化

### 3.7 物料管理器（UI 治理）

- 新增 `frontend/src/components/MaterialManager.vue`（对话框）：
  - 列表：所有自定义物料（名称/图标/分类/包含组件清单）
  - 操作：导入（文件/粘贴）、导出（`.vue` / `.html` / `.json`）、编辑（名称/图标/分类/描述）、**更新内容 = 从画布重新打包覆盖**、删除（二次确认）
  - 删除即删模板：展开模式下实例与定义零引用，删除不影响任何已存在页面（无需引用检查/版本历史）
- `MaterialList.vue` 的「自定义物料」tab 内放「管理物料」入口

## 四、后端扩展

### 4.1 存储与接口

| 方法 | 路径 | 说明 |
| :--- | :--- | :--- |
| GET | `/api/materials` | 物料清单（type=material） |
| POST | `/api/materials` | 注册/更新物料（manifest JSON，Zod 强校验，写队列复用） |
| GET | `/api/materials/:id` | 物料详情（含 schema 快照） |
| DELETE | `/api/materials/:id` | 删除（记录 SQLite 审计） |

- 存储：`backend/storage/materials/*.json`（每个物料一个文件，文件名 = `custom-xxx.json`），复用 `storageService.ts` 的并发写保护
- 校验：`schemaValidation.ts` 扩展 `MaterialManifest` schema（字段上限：label ≤ 50、description ≤ 200、summary ≤ 50 项、schema 节点数 ≤ 200、嵌套深度 ≤ 5）
- 审计：注册/更新/删除均写入 SQLite（复用现有日志控制器）

### 4.2 不做的事（明确边界）

- 本版本**不实现**运行时远程动态加载第三方 `.vue` 源码（vue3-sfc-loader 在线编译 / Module Federation 远程物料）——那是 v2.1+「扩展物料」方向，见第八节演进路线
- 本版本**不实现**复合物料的"黑盒引用"（拖入后保留为单一复合节点、物料升级联动实例）——那是 v2.1+ 演进方向
- 本版本**不实现** GraphQL 数据源 / Event Flow Orchestrator（沿用 CAE 规划）

## 五、里程碑拆分

### M1 — 复合物料闭环（画布 ↔ 物料）

**交付**：
1. shared 类型：`MaterialManifest` / `MaterialKind` 落地
2. `materialRegistry.ts` 运行时注册表 + `custom-` 命名空间隔离
3. 画布多选 + 「另存为物料」对话框（名称/图标/分类 + 勾选"同时下载导出文件"）+ 映射规则实现（包围盒/坐标归一化/inputs-outputs 聚合/扁平化 + visited 防环）
4. `addCompositeFromMaterial` 拖入实例化（坐标平移 + assignIds/rewriteTargets）
5. 后端 `/api/materials` CRUD + Zod 校验 + 存储 + 审计
6. `MaterialList.vue`「自定义物料」tab

**验收**：
- 选中任意节点组（含事件动作链、数据源、嵌套容器）→ 另存为物料 → 拖入新画布 → 结构断言测试通过（子树等价，仅 id 不同）
- 事件动作链 target 在实例化后指向新 id，动作可正常执行
- 内置物料列表不受影响，`custom-` 前缀不可被内置类型覆盖

### M2 — 自描述出码与导入管道（代码 ↔ 物料）

**交付**：
1. `generateMaterialBundle`：Vue/HTML 产物内嵌 `@lowcode-material` manifest 注释块；manifest `.json` 独立导出
2. `materialImport.ts` 导入管道：类型分派 → 注释块提取 → Zod 校验 → 注册；无注释块降级为空快照物料
3. 循环幂等回归测试：导出 → 导入 → 导出，结构 diff 稳定（除 id 外）

**验收**：
- `generateMaterialBundle` → 导入还原 → 拖入 → 出码，与原始手搭页面出码语义等价
- 连续循环 3 轮，每轮 diff 稳定，无 id 泄漏、无 target 悬空
- 消毒与长度上限生效；畸形 manifest 被拒绝且给出可读错误

### M3 — 物料治理与加固（收尾）

**交付**：
1. `MaterialManager.vue`：列表/导入/导出/编辑/重新打包/删除
2. 安全加固复核：DOMPurify、Zod、命名空间、深度限制、审计覆盖
3. README 文档索引更新（新增 v2.0.0 规划条目 + 能力描述）
4. 全量 CI 绿：typecheck → lint → test → build（前端测试预计 +30~40 项）

**验收**：

## 七、风险与决策点

| 决策点 | 本版本选择 | 理由 | 备选（后续版本） |
| :--- | :--- | :--- | :--- |
| 打包与导出的关系 | **一个入口「另存为物料」**：内部构造 manifest → 注册 + 可选编码文件。导出 = 打包 + 编码，无需独立入口 | manifest 是唯一中间表示，导出文件必须内嵌 manifest 才可再导入 | — |
| 复合物料渲染形态 | **展开为子树**（拖入即扁平化实例化） | 渲染/出码/编辑零新增分支，闭环最短 | 黑盒引用（v2.1） |
| 复合物料内部嵌套 | 打包时**扁平化**（展开嵌套复合物料） | 产物纯原子，出码/导入无需复合分支；visited 防环 | 保留引用（v2.2+） |
| 导入的物料是否可拖拽 | 仅**带 schema 快照**的可拖拽；空快照提示编辑 | 不对第三方代码做不可靠解析承诺 | 动态渲染器（v2.1） |
| 自描述载体 | **代码头部注释块** + 后端独立 `.json` 双轨 | 注释块使导出文件自包含、可移植；`.json` 便于结构化交换 | — |
| 用户物料命名 | `custom-` 前缀强制 | 与内置类型物理隔离，防覆盖 | 物料市场命名空间（v3.0） |
| 内置物料是否可覆盖 | 否（只读种子） | 保持平台核心稳定 | 企业版可配（v3.0） |
| 物料版本管理 | **本版本不做**（manifest 无 version 字段） | 展开模式实例与定义零引用，版本无运行时语义；改物料 = 改模板 | 黑盒引用模式引入（v2.1） |

**风险清单**：
- **循环引用**（物料 A 含物料 B 含物料 A）→ 打包时 visited + 深度上限检测，命中即拒
- **id 冲突**（多次拖入同一物料）→ 复用现有 `assignIds`，短哈希去重
- **事件 target 悬空**（两类：打包时指向子树外/图层；实例化后解析失败）→ 前者打包时剥离并告警（1.4.3），后者置空 + `executeActions` 安全跳过
- **manifest 体积**（schema 快照过大）→ 节点数 ≤ 200 上限 + 扁平化控制
- **循环幂等漂移**（每轮循环结构变化）→ M2 的 3 轮 diff 测试锁死
- **物料定义被误当目标**（拖入前即被动作链引用）→ 目标选择器只列出画布实例 id，物料面板条目不参与目标选择
