# 低代码前端平台 (Low-Code Frontend Platform) - 0.1.0 规划文档

## 1. 版本定位与核心愿景

在 **0.0.1 版本**中，我们成功完成了基于 `vue3-grid-layout` 的可视化网格画布、高端表单 (ProForm) 与高端表格 (ProTable) 物料拖拽、右侧抽屉配置以及 JSON 文件/SQLite 审计日志的双存储架构。

**0.1.0 版本** 的核心突破点在于**解决“数据联通、网络请求与行为事件驱动”问题**：
1. **数据源与 API 接口接入**：组件属性如何优雅地与后端 RESTful API / GraphQL 接口建立连接？
2. **请求参数与字段映射 (Parameter & Field Mapping)**：如何将页面组件的值（如表单筛选项、全局状态、路由参数）动态映射为 API 请求参数，并将 API 返回数据精确映射到表格/组件字段上？
3. **事件与动作机制 (Events & Actions Mapping)**：按钮点击、下拉改变、表格行操作等 UI 事件，如何抽象为灵活的“动作 (Action)”链条并建立解耦映射？
4. **人性化交互设计**：如何在侧边配置抽屉中提供极佳的可视化交互体验，让不写代码的用户也能完成复杂的接口绑定与动作链条编排？

## 2. 核心 Schema 扩展设计 (Data Source & Api Binding Schema)

为了支撑数据源连接与传参映射，我们需要扩展 `PageSchema` 与 `ComponentNode`，引入全局数据源 `dataSources` 与节点数据绑定 `dataSourceBinding`。

### 2.1 页面全局数据源定义 (`DataSourceSchema`)

```typescript
// 页面全局 API 数据源列表定义
export interface DataSourceSchema {
  id: string;               // 数据源唯一 ID (例: "ds_get_user_list")
  name: string;             // 别名/描述 (例: "查询用户列表API")
  url: string;              // 请求 URL (支持动态插值，如 "/api/users/{userId}")
  method: 'GET' | 'POST' | 'PUT' | 'DELETE';
  headers?: Record<string, string>;
  // 默认请求参数定义
  defaultParams?: Record<string, any>; // Query 或 Body 默认参数
  // 响应数据预处理 (可选 JS 表达式/函数)
  dataTransform?: string;    // 例如: "res.data.items" 或 "res.list"
}

// 扩展后的 PageSchema
export interface PageSchema010 {
  id: string;
  title: string;
  type: 'page' | 'component';
  meta: { author: string; description: string; version: string };
  // 页面全局响应式状态变量 (如 searchForm: { name: '' })
  state: Record<string, any>;
  // 全局数据源列表
  dataSources: DataSourceSchema[];
  // 画布组件节点
  children: ComponentNode010[];
}
```

### 2.2 组件节点 API 绑定模型 (`DataSourceBinding`)

```typescript
export interface DataSourceBinding {
  dataSourceId: string;     // 关联的全局 API 数据源 ID
  autoFetch: boolean;       // 是否初始化时自动调用
  // 1. 请求参数映射：如何把表单项或 State 映射到 API 的 query/body 传参
  paramMapping: {
    apiKey: string;         // 接口定义的参数名 (例: "keywords", "page_num")
    sourceType: 'state' | 'component_value' | 'static' | 'route_param';
    sourceValue: string;    // 对应的来源 (例: "searchForm.username" 或 "node_input_1.value")
  }[];
  // 2. 响应字段映射：如何把接口返回数据填充到当前组件的特定属性/列上
  responseMapping: {
    targetProp: string;     // 组件的目标属性 (例: "mockData" 或 "config.columns")
    dataPath: string;       // 响应 JSON 提取路径 (例: "data.records" 或 "data.total")
  }[];
}

export interface ComponentNode010 {
  id: string;
  type: string;
  label: string;
  layout: { x: number; y: number; w: number; h: number; i: string };
  props: Record<string, any>;
  attrs: Record<string, any>;
  config?: Record<string, any>;
  // 核心扩展：API 数据源绑定配置
  apiBinding?: DataSourceBinding;
  // 核心扩展：组件事件绑定模型 (详见第 8 章)
  events?: Record<string, EventRule>;
}
```

## 3. 传参映射与数据通信机制 (Parameter & Data Mapping)

实现组件属性与接口连接的核心在于“解耦”与“响应式追踪”：

```
+-------------------+             +--------------------+             +------------------+
| 组件A / 搜索表单   | 变量改变 -> | 页面全局 State Store | -> 触发请求  | 数据库 / Backend |
| (ProForm)         |             | (Pinia State)      |             | RESTful API      |
+-------------------+             +--------------------+             +------------------+
                                           │                                  │
                                     参数映射处理                        返回 JSON 响应
                                           │                                  │
                                           ▼                                  ▼
                                  +-------------------+              +------------------+
                                  | 封装组装 HTTP 请求 | ------------ | 数据映射器        |
                                  | (Axios/Fetch)     |              | (ResponseMapper) |
                                  +-------------------+              +------------------+
                                                                              │
                                                                         字段提取与填充
                                                                              │
                                                                              ▼
                                                                     +------------------+
                                                                     | 组件B / 高端表格  |
                                                                     | (ProTable Data)  |
                                                                     +------------------+
```

### 3.1 传参映射模式 (Request Parameter Mapping)
1. **静态常量 (Static)**：直接固定参数值，如 `pageSize: 10`, `status: "ACTIVE"`。
2. **全局状态联动 (State Bound)**：绑定到页面 `state.searchForm.keyword`，表单项变动时 API 参数自动同步。
3. **跨组件驱动 (Component Bound)**：指定监听另一个组件的值（如当选定 `Select` 树组件节点时，自动触发表格 `table_1` 刷新并带入 `dept_id`）。
4. **URL / 路由传参 (Route Param)**：获取页面 URL 查询参数（如 `?userId=1001`）。

### 3.2 响应映射与数据转换 (Response Field Mapping)
不同后端返回的数据格式可能千差万别（有的返回 `{ code: 200, data: [...] }`，有的返回 `{ result: { list: [...] } }`）。
- **字段路径选择器 (JSON Path Parser)**：允许用户输入 `data.records` 或使用可视化的 JSON 树挑选目标数组。
- **自定义数据转换函数 (JS Expressions)**：预留极简代码转换器，如 `data => data.map(item => ({ ...item, fullname: item.first_name + item.last_name }))`。

## 6. 代码质量与组件规范

1. **类型完备**：`DataSourceSchema`、`DataSourceBinding`、`EventRule`、`ActionHandler` 必须严格标注 TS 类型，禁止模糊隐式 `any`。
2. **极佳的可读性与模块解耦**：
   - 数据请求与映射逻辑独立封装在 `frontend/src/designer/executor/ApiExecutor.ts` 中。
   - 动作派发器封装在 `frontend/src/designer/executor/ActionDispatcher.ts` 中。
   - 配置面板拆分为 `DataSourceSelector.vue`、`ParamMappingTable.vue`、`EventActionEditor.vue` 独立单一职责组件。

## 7. 低代码数据联动与接口高级创新思考 (Advanced Ideas & Innovation)

在低代码平台演进过程中，数据绑定往往会遇到极具挑战的真实业务场景。以下梳理 5 个具有高度前瞻性与实用价值的**创新功能点**：

### 7.1 OpenAPI / Swagger / Postman 一键导入解析 (One-Click OpenAPI Import)
- 用户粘贴 Swagger / OpenAPI v3 JSON 链接，平台自动解析生成 `dataSources` 列表。

### 7.2 可视化无代码计算公式 (No-Code Formula / Expression Engine)
- 引入类似 Excel 的可视化公式引擎（例: `CONCAT(a, b)`, `IF(status==1, '启用', '停用')`），用户无需编写原生 JS。

### 7.3 智能防抖、缓存与静默请求 (Debounce, Cache & Silent Fetch)
- 支持设置防抖 (Debounce 300ms)、二级缓存 (Cache TTL) 与无感静默刷新。

### 7.4 模拟 Mock 数据研发模式 (Built-in Mock Server)
- 一键开启 Mock 模式，支持动态生成随机测试数据，让前端页面无阻碍完成布局调试。

### 7.5 错误异常处理与 Fallback UI 兜底
- 提供 `errorFallback` 属性，在接口报错时退回默认 Mock 兜底数据或占位 Empty 图案，保障生产环境健壮度。

## 8. 事件 (Events) 与动作 (Actions) 的抽象与响应式联动映射机制 ★ (新核心)

在实际业务开发中，光有“静态属性配置”和“只读 API 数据绑定”是不够的。**用户点击按钮、改变下拉框、双击表格行、提交表单** 时，系统需要做出响应。针对用户关注的“**按钮点击等怎么映射？要不要加概念事件或动作？它们之间怎么映射连接？**”，本章进行深度抽象与设计落地：

### 8.1 核心概念解耦：触发事件 (Event) vs 执行动作 (Action)

为了保证扩展性与极高可读性，我们将逻辑彻底拆解为 **触发端 (Event)** 与 **响应端 (Action)**，两者通过定义明确的 Schema 进行“多对多”映射联通：

```
+------------------------------------------------------------------------------------+
|                                    事件与动作解耦模型                                |
+------------------------------------------------------------------------------------+
| 【触发端: Event Trigger】                                                          |
|  - 按钮/图片/卡片: onClick (点击事件)                                              |
|  - 输入框/下拉框: onChange / onBlur (变动/失焦事件)                                 |
|  - 高端表格: onRowClick / onPageChange / onSearch (行点击/翻页/搜索事件)             |
+------------------------------------------------------------------------------------+
                                         │
                                   【事件派发器 Event Dispatcher】
                                         │  按顺序串联执行 (Action Chain)
                                         ▼
+------------------------------------------------------------------------------------+
| 【执行端: Action Handler】                                                         |
|  Action 1: 触发 API 请求 (Fetch API) ----> 带入关联参数并刷新指定表格               |
|  Action 2: 修改页面全局状态 (State Mutation) -> 修改 state.currentId              |
|  Action 3: 控制弹窗/抽屉 (Modal Control) ---> 打开新增/编辑弹窗                     |
|  Action 4: 页面/路由跳转 (Navigation) -----> 跳转到详情页                            |
|  Action 5: 消息提示 (Notification) ---------> 弹出 ElMessage 成功/警告通知          |
|  Action 6: 自定义 JS 脚本 (Custom Script) -> 复杂逻辑补丁                         |
+------------------------------------------------------------------------------------+
```

---

### 8.2 核心 Schema 抽象定义 (`EventSchema`)

```typescript
// 1. 动作 (Action) 单元定义
export interface ActionHandler {
  id: string;                               // 动作单元唯一 ID
  type: 'fetch_api' | 'mutate_state' | 'open_modal' | 'navigate' | 'notify' | 'custom_script';
  name: string;                             // 动作别名 (如 "刷新用户表格", "弹出提示")

  // 动作的具体参数 Payload
  payload: {
    // 触发网络请求
    targetApiId?: string;                   // 指定要调用的 API 数据源 ID
    refreshComponentIds?: string[];         // 请求成功后需要被刷新的目标组件 ID 列表

    // 状态修改
    stateKey?: string;                      // 要修改的全局 state 字段
    stateValue?: any;                       // 赋予的新值 (支持上下文插值如 "$event.row.id")

    // 控制弹框
    modalId?: string;
    modalAction?: 'open' | 'close';

    // 页面跳转
    url?: string;
    target?: '_self' | '_blank';

    // 消息提示
    notifyType?: 'success' | 'warning' | 'info' | 'error';
    notifyMessage?: string;

    // 自定义 JS 代码
    code?: string;
  };
}

// 2. 组件事件规则映射定义 (EventRule)
export interface EventRule {
  eventName: string;                        // 事件名 (如 "click", "change", "row-click")
  enabled: boolean;
  // 动作链条 (Action Chain)：支持一个事件依次触发多个动作
  actions: ActionHandler[];
}
```

## 9. 最佳实践案例：搜索按钮与表格删除操作如何连接映射？

### 案例 1：搜索按钮 (ElButton) 点击，带动后端表格 (ProTable) 刷新

1. **触发端**：选择画布上的【搜索按钮】`button_search`，切换到【事件与动作】Tab。
2. **事件选择**：选中 `onClick` 点击事件。
3. **添加动作 (Add Action)**：
   - 动作类型选择：`fetch_api` (触发网络请求)。
   - 关联 API：选择 `ds_get_users` (查询用户列表 API)。
   - 映射传参：自动将页面 `state.searchForm` 收集的搜索条件作为 Query 参数传入 API。
   - 影响目标：选择关联刷新 `table_user_list` 组件。
4. **效果**：用户点击搜索按钮，触发 `Action` -> 执行 `ApiExecutor` 发请求 -> `ProTable` 自动用最新数据重绘。

---

### 案例 2：表格 (ProTable) 行数据删除按钮点击

1. **触发端**：选中 ProTable 内部的操作列按钮 `delete` (触发事件 `onRowDelete`)。
2. **动作链条 (Action Chain)**：
   - **Action 1** (`fetch_api`)：调用后端 `DELETE /api/users/{$event.row.id}` 接口。
   - **Action 2** (`notify`)：调用成功后触发成功提示“删除成功”。
   - **Action 3** (`fetch_api`)：自动重新触发表格刷新 API `ds_get_users`。

## 10. 事件与动作的可视化交互界面思考 (Action Orchestrator UX)

针对“怎样的交互比较好”，经过对比分析，建议在右侧抽屉提供 **【卡片链条式动作编排器 (Chain Action Editor)】**：

```text
+-----------------------------------------------------------------------+
| [属性 Props] [高级 Config] [数据源 API] [事件与动作 ⚡] [原生 Attrs]    |
+-----------------------------------------------------------------------+
|  监听事件: [ 点击事件 (onClick) ▼ ]                                    |
|                                                                       |
|  触发动作链条 (Action Chain):                                          |
|  +-----------------------------------------------------------------+  |
|  | 动作 1: 触发 API 请求 (fetch_api)                       [删] [升] |  |
|  | 关联数据源: [ GET /api/users/list                   ▼ ]         |  |
|  | 刷新目标组件: [ ☑ 用户表格 (table_1)  ☑ 计数器 (tag_1) ]          |  |
|  +-----------------------------------------------------------------+  |
|                                   │ (顺序向下执行)                    |
|                                   ▼                                   |
|  +-----------------------------------------------------------------+  |
|  | 动作 2: 弹出操作提示 (notify)                           [删] [降] |  |
|  | 提示类型: [ Success 成功 ▼ ]                                     |  |
|  | 提示文本: [ "用户数据查询/刷新完成！"                        ]   |  |
|  +-----------------------------------------------------------------+  |
|                                                                       |
|  + 新增动作节点 (Add Action Step)                                     |
+-----------------------------------------------------------------------+
```

### 交互优势：
1. **零学习成本**：以积木块卡片方式从上至下串联动作（Action 1 -> Action 2），直观易懂。
2. **灵活可插拔**：用户可以自由拖拽调整动作执行顺序、随时添加或删除某个动作节点。
3. **安全提示**：提供上下文变量插值提示（如 `$event.row` 表示当前行数据，`$state` 表示全局状态），防止配置错乱。
