# 低代码前端可视化平台 (Low-Code Studio) - v0.4.0 规划文档与最佳落地建议

> **版本定位**：高级逻辑编排、数据源建模、可视样式精细化与物料 SDK 扩展
> **状态**：规划中 (Drafting)
> **前置版本**：v0.0.1 (基础平台与组件化架构), v0.2.0 (自动保存/代码导出/撤销重做/快捷键), v0.3.0 (响应式多端/嵌套容器/动态表达式)

## 🎯 0.4.0 核心目标

在 0.3.0 实现响应式多端布局、嵌套容器和表达式解析的基础上，0.4.0 专注于提升 low-code 平台的**业务逻辑编排能力**、**复杂数据建模**与**自定义扩展生态**，使平台能够支撑中大型复杂企业级前端应用的开发。

---

## 📋 功能清单与演进规划

### 1. 节点式可视化逻辑流编排 (Workflow / Logic Graph Editor)
- **目标**：取代单一的内联 JavaScript 事件调用，实现拖拽式节点逻辑流。
- **功能特性**：
  - 节点类型：事件触发节点（点击/表单变更/加载）、API 请求节点、条件分支节点（If/Else）、数据转换节点、UI 交互节点（弹窗/Toast/路由跳转）。
  - 支持节点连线与参数传递（流转上下文数据）。
  - 可视化调试工具：单步运行逻辑节点并输出日志面板。

### 2. 在线 API 数据源建模与 Mock 仿真 (Data Source Modeling & Mock Engine)
- **目标**：解耦前端组件与后端固定接口，支持灵活配置 RESTful / GraphQL 数据源。
- **功能特性**：
  - **数据源配置**：支持配置 BaseURL、请求头 (Headers)、鉴权 Token、请求/响应拦截器。
  - **数据模型定义 (Data Models)**：定义实体结构与字段类型（String, Number, Date, Object, Array）。
  - **Mock 仿真服务器**：根据数据模型自动生成符合 Swagger/OpenAPI 标准的在线 Mock 接口数据。

### 3. 可视化 CSS 与样式微调编辑器 (Visual CSS & Style Inspector)
- **目标**：提供精细化样式编辑器，满足个性化 UI 设计需求。
- **功能特性**：
  - **盒模型编辑器**：可视化调整 Margin, Padding, Border, Box-shadow。
  - **Flexbox / Grid 布局面板**：直观配置 `flex-direction`、`justify-content`、`align-items`、`gap`。
  - **主题与 CSS 变量系统**：一键切换 Element Plus 主题色（Primary Color, Light/Dark Mode）与全局 CSS 变量。

### 4. Schema 版本对比与可视化 Diff 工具 (Schema Versioning & Visual Diff)
- **目标**：保障多人协作安全性，支持历史版本追踪与变更回滚。
- **功能特性**：
  - 支持保存历史版本快照，标注变更说明。
  - 提供左右双栏控制 JSON Schema 与 UI 渲染图层的对比 (Visual Diff)。
  - 支持一键回滚恢复至指定版本快照。

### 5. 第三方自定义物料插件 SDK (Material Plugin SDK)
- **目标**：开放低代码物料生态，允许开发者自由扩展第三方 UI 库与自定义组件。
- **功能特性**：
  - 提供 `defineMaterial()` 标准 SDK 声明接口。
  - 支持动态加载远程 UMD / ES Module 物料组件。
  - 物料市场 (Material Marketplace) 概览与一键启用/禁用控制。

## 💡 六大最佳架构落地建议 (Architectural Best Practices for v0.4.0)

针对 v0.4.0 的高级特性落地，提炼出以下 6 项经过业界大厂验证的技术架构建议：

### 1. 表达式与逻辑脚本的安全沙箱隔离 (JS Execution Sandbox)
- **痛点**：在动态表达式解析或节点逻辑流执行中，直接使用 `eval()` 或 `new Function()` 存在被 XSS 攻击注入恶意代码（如 `window.location` 篡改或 `cookie` 盗取）的安全风险。
- **最佳建议**：
  - 引入 **Web Worker** 或 **`iframe` 沙箱** 处理自定义逻辑与数据转换。
  - 在运行时对可注入的上下文变量建立只读代理（`Proxy`），屏蔽 `window`、`document` 与敏感 DOM API，仅向自定义逻辑开放 `state`、`params` 和 `helpers`。

### 2. 细粒度响应式状态衍生与计算依赖链 (Derived State & Computed Store)
- **痛点**：随着组件数量增多，联动逻辑会导致不必要的全画布组件重新渲染（Re-render）。
- **最佳建议**：
  - 在 Pinia 状态管理中，将页面全局状态与衍生状态区分开，建立**响应式依赖追踪拓扑树**。
  - 使用 Vue 3 原生 `computed` 建立节点级缓存，仅当某组件订阅的数据字段变更时才触发其局部更新。

### 3. 混合物料加载与插件解耦 (Hybrid Material Integration)
- **痛点**：所有物料如果都以 Vue SFC 形式编译在主包中，会导致打包产物极大；如果全都是远程 UMD 模块，则渲染性能受限。
- **最佳建议**：
  - 采用 **“内置核心物料 (.vue) + 远程扩展物料 (.js UMD/ESM / Web Component)” 的混合架构**（参考 `docs/implemented/MATERIAL_SPECIFICATION.md`）。
  - 内置物料保障画布核心表单/表格的极致性能与干净出码，扩展物料通过 `defineMaterial()` 规范解耦，支持无需发布主工程的热插拔更新。

### 4. 增量 JSON Patch 版本控制与高效 Diff 算法 (RFC 6902 JSON Patch & Diff)
- **痛点**：每次修改页面均保存全量 Schema，会导致后端存储开销大，且版本对比计算卡顿。
- **最佳建议**：
  - 采用 **RFC 6902 JSON Patch 规范** 记录 Schema 变更轨迹（仅保存 `add` / `replace` / `remove` 操作数组）。
  - 在 Schema 比对可视化视图中，通过 AST 分析仅重新渲染发生属性或结构变更的节点，避免比对时的全画布闪烁。

### 5. AI Copilot 自然语言辅助生成 Schema (AI-Driven Schema Generation)
- **痛点**：手动拖拽复杂大表单或大表格依然耗时。
- **最佳建议**：
  - 在 0.4.0 引入 **AI Copilot 对话助手**，支持通过自然语言（例如：“帮我生成一个包含姓名、手机号、部门下拉框以及提交重置按钮的员工注册表单”）自动输出标准的 JSON Schema 节点并一键插入画布。

### 6. 画布可视化标尺与吸附对齐参考线 (Canvas Ruler & Alignment Guides)
- **痛点**：组件在自由或网格拖拽时，缺乏精准的像素级辅助线指导。
- **最佳建议**：
  - 在 Canvas 图层上层叠加 SVG 参考线绘制层，在拖拽或缩放组件时，实时显示与邻近组件的水平/垂直对齐吸附线（如居中吸附、顶端吸附）及距离数值（如 12px）。

## 🏗️ 技术架构要求

1. **代码规范与解耦**：
   - 逻辑流引擎独立封装为 `frontend/src/utils/workflow/` 模块，保持逻辑与 UI 组件渲染分离。
   - 数据源模块保持 Component-API-Event 三角解耦模型。
2. **性能与稳定性**：
   - 大型 Workflow 图视图采用 Canvas / SVG 虚拟渲染，确保 100+ 节点无卡顿。
3. **可读性与可维护性**：
   - 严格的 TypeScript 类型定义，全局导出的类型申明统一存放于 `types/` 目录。
