# 低代码前端可视化平台 (Low-Code Studio) - v1.6.0 正确性与一致性加固规划

> **版本定位**：修正 v1.5.0 审查中的出码错误、设计器与出码不一致、存储竞态，并补上已承诺但未落地的审计差异、历史栈和组件 I/O 校验
> **状态**：规划中 (Planned)。本文件只定义范围与验收，不含实现
> **前置版本**：v1.5.0（出码白名单、属性撤销、图层编辑、数据源请求约束）
> **平台定位约束**：纯前端搭建 + 出码，**不生成后端代码**。数据请求仍由浏览器 `fetch` 访问已有 REST API

---

## 一、为什么做这一版

v1.3.0 到 v1.5.0 已经接上数据源、表达式、动作链和出码隔离。审查确认这些能力在单表单、无换行 URL、已绑定数据源的主路径上能工作，但下面几类输入会生成坏代码、空表格，或让设计和导出各走各的。

v1.6.0 把审查清单全部收口。完整管道编排和 GraphQL 仍不在本版，原因见文末范围边界。

## 二、P0 — 出码必须能运行

### P0-1 用户字符串不得打断生成脚本

**现状**：`renderScriptSetup` 把 `apiBinding.url` 拼进 `// 数据源:` 行注释，只做了 HTML 转义，不去掉换行。`renderOptionsData` 同样把 URL 放进 `data()` 的行注释。URL 中的换行会使后续文本变成可执行代码。

**方案**：

- 凡是进入 JavaScript 注释或对象字面量注释的用户文本，走现有 `safeComment`（去掉 `\r` / `\n`），再按上下文决定是否 HTML 转义。
- 进入 `<script>` 或 SFC 脚本的自定义 HTML / 生命周期脚本继续用 `embedJsString` / `escapeScriptClose`。
- 属性名只允许 `[A-Za-z_][A-Za-z0-9_:-]*`，其余丢弃，不拼进模板。
- 写进 `style=""` 的 `direction`、`padding` 等值去掉 `;`、`{}`、`<`、换行，避免在声明外再追加规则。

**验收**：URL 为 `http://example.com\nconst injected = 1` 时，SFC 与 HTML 产物中 `injected` 只出现在字符串或单行注释内，不成为独立语句。属性名 `"><img` 不出现在模板里。

### P0-2 多表单提交 / 重置按 formId 分支

**现状**：`handleSubmit` / `handleReset` 把每个表单 id 写成独立的真值三元表达式，没有和 `formId` 比较。两个及以上 `pro-form` 时生成相邻表达式，语法非法。单个表单能跑，是因为非空字符串恒为真。SFC 与 HTML（options API）都是这一写法。

**方案**：生成 `if (formId === "<id>") return formData_<ident>` 链，或一张 id → ref 的查找表。找不到 id 时返回空并直接 return。SFC 与 HTML 使用同一规则。

**验收**：两个 `pro-form` 的产物能通过 TypeScript 解析（或等价的脚本语法检查）；调用 `handleSubmit("第二个表单 id")` 只读到第二个 `formData`。

### P0-3 输入框和开关拥有自己的数据 ref

**现状**：`el-input`、`el-switch` 的模板绑定 `formData_<id>`，`renderScriptSetup` 只给 `pro-form` 声明该 ref。导出页面运行时变量不存在。

**方案**：每个 `el-input` / `el-switch` 在 SFC 中声明 `ref`，在 HTML 的 `data()` 中声明同名初始值（字符串输入为 `''`，开关为 `false`，或取 `props.value` 的静态默认值）。`v-model` 继续绑定该字段。

**验收**：只含一个输入框或一个开关的页面，产物中声明与模板引用成对出现。

### P0-4 未绑定数据源时，设计器表格显示占位数据

**现状**：`ProTable` 的占位行写在 `loadData()` 里，`onMounted` 仅在有 `apiBinding.url` 时调用。`rows` 初始为 `[]`，`totalCount` 初始为 `4`。出码在没有数据源时仍写入「张三 / 李四」。

**方案**：无 URL 时在 `onMounted` 填入与出码相同的两行占位数据，并把 `totalCount` 设为行数。有 URL 时逻辑不变。占位数据抽成一处常量，设计和出码共用，避免再次分叉。

**验收**：新拖入的高端表格在设计器中能看到占位行；配置 URL 后改为请求结果；出码里的占位行与设计器常量一致。

## 三、P0 — 设计器与出码行为对齐

### P0-5 表格行操作执行动作链，打开弹窗带上载荷

**现状**：设计器 `ProTable.handleAction` 只弹消息。出码的「查看」按钮调用 `handleRowAction(表格 id)`，不按 `config.actions` 分发，也不读取该节点的事件规则。`executeAction` 的 `open_dialog` 忽略 `payload`。

**方案**：

- 行按钮的 `eventKey` 对应该节点 `events[eventKey]`。设计器点击行按钮时调用 `executeActions`，`event` 为 `{ row, eventKey }`。
- 出码为每个行按钮生成点击，进入同一个 `handleNodeClick(nodeId, { row, eventKey })`，按 `eventKey` 选择动作链。没有配置事件时保留现在的消息提示。
- `open_dialog` 在显示图层之前，把 `payload` 里可求值的字段写入页面 `state`（与 `set_state` 相同的求值规则）。导出的语句做同样的赋值，再把对话框 ref 设为 `true`。

**验收**：表格行按钮配置 `click` → `set_state` + `open_dialog` 后，设计器预览和导出页面都能打开对应弹窗，且 `state` 中能读到当前行。

### P0-6 导出页面跟随分页

**现状**：设计器翻页会写 `state.page` 并重新请求。SFC 只有 `v-model:current-page`，没有翻页回调，请求参数也不含当前页。

**方案**：出码的分页组件在页码变化时更新该表的 `currentPage` ref，并再次调用 `loadData_<id>`。请求在已有 `params` 之外补上 `page`（当前页）和 `size`（固定 10，与现有模板 `:page-size="10"` 一致）。若 `params` 已含同名键，以用户配置为准，不覆盖。

**验收**：带 `apiBinding` 的表格产物在页码变化后会再次 `fetch`，查询串包含当前页。

### P0-7 组件属性上的表达式在出码中求值

**现状**：画布通过 `parseExpression` 渲染 `{{ }}`。出码除数据源 URL 和动作 payload 外，把属性原样 HTML 转义，导出页面显示花括号原文。

**方案**：复用 `renderUrlExpr` / `inlineExpr` / `canInlineExpression`。整段 `{{ expr }}` 且解释器接受时，文本节点改为插值，组件属性改为绑定表达式。解释器拒绝或含 `</` 时退回转义后的字符串字面量，与 v1.5.0 白名单相同。

**验收**：按钮文案 `{{ state.name }}` 在产物中绑定 `state.name`；`{{ 1) || alert(1) }}` 仍是字符串，不成为调用。

### P0-8 图层初始可见性以 Schema 为准

**现状**：`addLayer` 把新图层 `visible` 设为 `true`，Loading 立即盖住设计器。出码里对话框恒为 `ref(false)`，Loading 恒为 `ref(true)`，忽略 `layer.visible`。

**方案**：新建对话框和 Loading 默认 `visible: false`。自定义 HTML 仍默认可见，方便编辑。SFC 与 HTML 的初始 ref / data 使用 `layer.visible`。已保存的旧 Schema 保持文件中的布尔值，不在读取时改写。

**验收**：新建 Loading 不遮住设计器；把某对话框 `visible` 存为 `true` 再导出，产物初始值为 `true`。

## 四、P1 — 标识、复制与存储

### P1-1 粘贴重写整棵子树的 id

**现状**：`pasteNode` 只改根节点 `id` 和 `layout.i`，子节点 id 原样保留。

**方案**：深拷贝后按前序为根和全部子孙生成新 id，并同步 `layout.i`。事件动作的 `target` 若指向本次复制出来的旧 id，改写到新 id；指向树外的 id 保持不变。

**验收**：粘贴一个带两个子节点的容器后，三个 id 都是新的，且互不相同。

### P1-2 出码变量名冲突时加区分后缀

**现状**：`safeIdent` 把 `-` 等字符换成 `_`，`a-b` 与 `a_b` 生成同一个 `formData` / `loadData` 名。

**方案**：同一页面内标识符冲突时，在安全化结果后追加 `_` + 原 id 的短哈希（稳定、仅含 `[a-z0-9]`）。模板、脚本、HTML data/methods 使用同一函数。

**验收**：同一 Schema 含 id `a-b` 与 `a_b` 的两个输入框时，产物中两套变量名不同，且模板引用与声明一致。

### P1-3 备份按类型分目录，版本号和删除进入写队列

**现状**：page 与 component 的备份都落在 `storage/backups`，相同 id 互相覆盖。`saveSchema` 控制器在队列外读取旧版本再入队，并发保存会丢掉一次递增。`deleteSchema` 不入队，可与写入交错。

**方案**：

- 备份目录改为 `<pagesDir>/backups` 与 `<componentsDir>/backups`。恢复、列表、轮转都使用该目录。
- 读旧版本、递增、轮转、原子替换放进同一个按 `type + id` 区分的队列任务。
- 删除使用同一把队列，避免写到一半被删掉后又被 rename 写回。

**验收**：相同 id 的 page 与 component 各保存两次，备份文件分别留在两个目录。并发两次保存后版本号相差 1。删除进行中触发保存，最终磁盘上不存在该 id 的半截临时文件。

## 五、P1 — 请求与状态写入的安全约束

### P1-4 设计器数据源跟随重定向时逐跳校验

**现状**：`assertFetchableUrl` 只拒绝 `169.254.169.254` 和 `metadata.google.internal`。`fetch` 默认跟随重定向，中间跳转可以绕过这份名单。

**方案**：

- 设计器 `ApiExecutor` 使用 `redirect: "manual"`。收到 301/302/303/307/308 时解析 `Location`，对绝对地址或站内相对地址再次调用 `assertFetchableUrl`，通过后才继续，最多 3 跳。
- 拒绝 link-local、云元数据主机名、十进制/十六进制写法以及 IPv6 映射到这些地址的形式。
- **保留** `localhost`、`127.0.0.1` 和私网地址。设计器需要请求用户自己的本地 API，不能一刀切。
- 出码产物里的 `fetch` 同样使用 `redirect: "manual"` 和最多 3 跳的辅助函数，避免生成的页面比设计器更宽松。相对路径（站内 `/`）保持允许。

**验收**：指向会 302 到 `http://169.254.169.254/` 的 URL 在设计器试请求和生成代码的运行时都被拒绝。`http://127.0.0.1:<port>/api/...` 仍可请求。

### P1-5 `set_state` 不接受原型链键

**现状**：`Object.assign(scope, payload)` 会把 `__proto__` 交给赋值语义。

**方案**：`set_state` 与出码生成的赋值跳过 `__proto__`、`prototype`、`constructor`。键名用 `JSON.stringify` 写入下标赋值，不使用展开合并。

**验收**：payload 含 `__proto__` 时页面 `state` 不因此改变 `Object.prototype`，其余键照常写入。

### P1-6 自定义 HTML 预览与出码使用同一份文档

**现状**：设计器对 `htmlCode` 做 DOMPurify，出码的 srcdoc 原样拼接。设计器按小写 `</script>` 拆分，出码用大小写不敏感替换。

**方案**：抽出唯一的 srcdoc 构建函数，设计器 iframe 和 `buildCustomHtmlSrcdoc` 都调用它。`htmlCode` 一律消毒；脚本只来自 `scriptMounted` / `scriptUpdated` / `scriptUnmounted`，闭合标签按大小写不敏感处理。iframe 保持 `sandbox="allow-scripts"` 且不带 `allow-same-origin`。

**验收**：`htmlCode` 含 `<script>alert(1)</script>` 或 `</SCRIPT>` 时，设计器预览和 SFC 中的 srcdoc 字符串一致，且不能提前结束脚本标签。

### P1-7 认证说明与比较方式

**现状**：未配置 `API_KEY` 时接口开放，这是本地开发的既定行为。配置之后，前端把 `VITE_API_KEY` 打进包里，比较使用普通字符串相等。

**方案**：本版不引入登录系统。启用密钥时改为定长比较。README 写明：这个密钥会随前端包下发，只能挡住随意扫描的本机端口，不能当作用户口令。未配置时行为不变。

**验收**：错误密钥返回 401；未配置时保存接口仍可访问；README 有上述说明。

## 六、P2 — 审查中的待优化项

### P2-1 审计日志记下结构化差异

**现状**：界面标题写「JSON Diff」，`details` 只存标题、节点数量和布局摘要。

**方案**：保存时在写队列内对比上一份 Schema，把 RFC 6902 JSON Patch 数组放进 `details.patch`（单次最多 200 条，超出则只记 `truncated: true` 和节点数量）。日志弹窗展示 patch 操作列表。没有上一份文件的首次保存明确标成「首次保存」，不再叫 Diff。

**验收**：连续两次保存，第二次日志的 `details.patch` 能反映标题或某个 `props` 的变化。

### P2-2 撤销栈改为补丁，拖拽只记松手

**现状**：每一步都是整页 `JSON.stringify`。拖拽过程中的 `layout-updated` 会把中间坐标记进历史。

**方案**：

- 历史条目改为相对上一步的 JSON Patch；每隔 10 步存一份全量快照作为基线，避免补丁链过长。
- 撤销/重做的对外行为不变：`canUndo` / `canRedo`、属性合并输入、回放时 `suppressHistory`。
- 画布只在 `dragstop` / `resizestop` 记一步，移动过程不入栈。
- 体积上限沿用现在的约 1.5MB 策略，按补丁文本长度计算。

**验收**：拖拽一次松手后只增加一步撤销；连续改同一个属性仍合并成一步；撤销后 Schema 与改之前一致。现有 `designerStore` 撤销测试继续通过。

### P2-3 自制组件入参的必填提示

**现状**：`docs/implemented/COMPONENT_IO_SPECIFICATION.md` 已定义 Pro 组件入参/出参契约，属性抽屉没有必填校验。

**方案**：在物料注册上为 `pro-table`、`pro-form`、`pro-container` 增加 `inputs` / `outputs` 声明（字段名、类型、是否必填）。属性抽屉在缺必填项时显示警告，不阻止保存，也不在画布上因警告而停止渲染。`customValidator` 函数字符串本版不执行。

**验收**：删空 `pro-table` 的 `columns` 后，抽屉出现必填警告；补回列定义后警告消失。

## 九、范围边界（本版明确不做）

- 不实现 `docs/implemented/PIPELINE_ORCHESTRATION.md` 的 `beforeTransform` / `scriptTransform` / `afterTransform` 管道，也不做页面路由跳转编排。
- 不做 GraphQL、WebSocket、`functions` 业务脚本。
- 不生成后端代码，不引入 RBAC / SSO。
- 不把 `VITE_API_KEY` 改造成用户登录。浏览器里的前端包拿不到真正的服务端机密。
- 不拦截用户主动配置的本机和私网数据源。
- 历史栈改为补丁，但不改为多人协同的 CRDT。
