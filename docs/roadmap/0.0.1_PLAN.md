# 低代码前端平台 (Low-Code Frontend Platform) - 0.0.1 规划文档

## 1. 项目概述与愿景

### 1.1 项目简介
本项目旨在打造一款高性能、高可扩展性、高度模块化的**低代码前端可视化平台**。用户可以通过可视化拖拉拽的方式快速搭建前端页面，或者将常用的 UI 与逻辑封装并导出为可复用的前端 JS/Vue 组件。

### 1.2 核心目标与首期突破点 (0.0.1 版本)
- **第一步聚焦：高端表单与高端表格拖拽生成**：
  - **高端组件库**：集成功能丰富的高端表单（多列联动、校验规则、动态增减项）与高端表格（分页、筛选、自定义列、排序、行操作列）。
  - **自动化配置生成**：用户拖拽表单/表格组件后，系统自动生成对应的标准 JSON 配置项。
- **UI 交互架构**：
  - **主内容区**：大屏可视化展示拖拽画布（基于 `vue3-grid-layout` 网格）。
  - **侧边弹框/抽屉 (Side Drawer)**：选中节点后，侧框实时呈现当前表单/表格的详细配置修改界面及 JSON 实时预览。
- **存储架构策略**：
  - **JSON 存储**：页面与组件配置项直接持久化存储为本地 `.json` 文件。
  - **SQLite 存储**：用于记录用户的操作日志 (Operation Audit Log) 及页面版本变更轨迹。
- **工程质量标准**：严谨的代码结构、强类型定义、高度组件化解耦、极致的代码可读性与可维护性。

## 3. 核心设计规范与 Schema 结构

系统核心由 **JSON Schema** 驱动，实现 `Schema <-> 画布渲染 <-> 源码生成` 的双向转换。

### 3.1 页面/组件 Schema 规范 (`PageSchema`)

```typescript
export interface PageSchema {
  id: string;             // 页面或组件唯一 ID (例如: "page_001")
  title: string;          // 名称
  type: 'page' | 'component'; // 标注是完整页面还是自定义组件
  meta: {
    author: string;
    description: string;
    version: string;
  };
  // 页面全局状态与数据源定义
  state: Record<string, any>;
  // 网格布局容器及节点列表
  children: ComponentNode[];
}

export interface ComponentNode {
  id: string;             // 节点唯一 ID (如 "table_node_1")
  type: 'pro-table' | 'pro-form' | 'el-button' | 'el-input' | string; // 组件类型
  label: string;          // 物料显示名称
  // vue3-grid-layout 位置与尺寸配置
  layout: {
    x: number;            // 网格 X 坐标
    y: number;            // 网格 Y 坐标
    w: number;            // 网格宽度 (栅格列数)
    h: number;            // 网格高度 (栅格行数)
    i: string;            // 布局唯一标识 (一般同 id)
  };
  // 原生/扩展组件的 Props 与 Attrs
  props: Record<string, any>;
  attrs: Record<string, any>;
  // 高端表格/表单特有配置项定义
  config?: ProTableConfig | ProFormConfig;
  // 自定义内联样式/CSS类
  style: Record<string, any>;
  // 事件绑定 (如 onSearch, onRowClick)
  events: Record<string, EventHandler>;
  // 子节点 (支持容器嵌套)
  children?: ComponentNode[];
}

// 高端表格组件配置 Schema
export interface ProTableConfig {
  columns: {
    prop: string;
    label: string;
    width?: string;
    sortable?: boolean;
    align?: 'left' | 'center' | 'right';
    slotName?: string;
  }[];
  pagination: {
    enabled: boolean;
    pageSize: number;
  };
  actions?: {
    label: string;
    type: string;
    eventKey: string;
  }[];
}

// 高端表单组件配置 Schema
export interface ProFormConfig {
  layout: 'inline' | 'horizontal' | 'vertical';
  labelWidth: string;
  items: {
    field: string;
    label: string;
    component: 'input' | 'select' | 'date' | 'switch' | 'radio';
    placeholder?: string;
    rules?: any[];
  }[];
}

export interface EventHandler {
  type: 'custom_js' | 'page_jump' | 'open_modal' | 'refresh_table';
  code?: string;          // 自定义 JS 代码段
  target?: string;
}
```

### 5.2 SQLite 数据库数据模型：`operation_logs` (操作日志表)
| 字段名 | 类型 | 约束 | 描述 |
| :--- | :--- | :--- | :--- |
| `id` | INTEGER | PRIMARY KEY AUTOINCREMENT | 日志主键 |
| `page_id` | VARCHAR(36) | NOT NULL | 关联的页面/组件 ID |
| `action` | VARCHAR(50) | NOT NULL | 操作类型 (`CREATE_PAGE`, `UPDATE_SCHEMA`, `DELETE_PAGE`, `EXPORT_CODE`) |
| `operator` | VARCHAR(50) | NOT NULL DEFAULT 'system' | 操作者身份 |
| `details` | TEXT | NULL | 操作变动细节描述（JSON 格式） |
| `created_at` | DATETIME | DEFAULT CURRENT_TIMESTAMP | 日志记录时间 |

## 7. 代码与质量规范 (Quality & Style Guide)

1. **强类型与严谨声明**：
   - 所有 Schema 数据结构与配置项必须具有完备的 TypeScript interface / type 定义。
   - 杜绝隐式 `any`，确保配置变更时有完备的编译时类型检查与代码提示。

2. **严格组件化与单职责原则 (SRP)**：
   - 界面严格解耦：
     - `CanvasContainer`: 主内容渲染画布
     - `ProTableWidget` / `ProFormWidget`: 运行时高端组件包装器
     - `PropertyDrawer`: 侧边配置弹框/抽屉
     - `SchemaJsonViewer`: 配置项 JSON 源码展示器
   - 物料属性配置项采用工厂机制，保持高扩展性。

3. **可维护性与扩展性**：
   - 新的高端表单/表格控件接入只需在 `registry` 中增加配置 Schema 与渲染组件，无须改动主引擎代码。
   - 前后端代码排版规范统一（ESLint + Prettier），代码工整，多写注释。

## 8. 拖拽物料与 Props/Attrs 动态配置交互设计思考

关于**带拖拽组件**以及**如何配置各种 Props 与 Attrs**，低代码平台的设计核心在于“物料描述能力”与“配置界面的可理解性”。以下梳理几种常见的交互模式与设计思考（含优劣势对比与选型思考）：

### 8.1 拖拽与落域 (Drag & Drop to Canvas) 交互设计

#### 交互流程：
1. **物料面板 (Left Palette)**：列出高端表单、高端表格、通用 UI 控件。用户可 `dragstart` 触发拖拽。
2. **画布投射区 (Main Canvas)**：
   - 基于 HTML5 Drag and Drop API 或 `vue3-grid-layout` 的 Drop 事件。
   - 拖拽拖入画布上方时，画框显示高亮虚线框（Drop Indicator），展示预测落点与宽度/高度。
3. **节点实例化 (Node Instantiation)**：
   - 释放鼠标时，生成带有默认 `props`、`attrs` 和唯一 `id` 的 `ComponentNode`，追加至 Pinia store 的 `children` 数组。
   - 画布根据节点 `layout` 字段用 `vue3-grid-layout` 自动布局渲染。

---

### 8.2 Props 与 Attrs 的区分与配置映射

低代码平台中，UI 组件包含两类配置：

| 维度 | Props (组件属性) | Attrs (原生/HTML属性) |
| :--- | :--- | :--- |
| **定义** | 组件显式定义的 `defineProps` 强类型参数（如 `size`, `disabled`, `columns`, `rules`） | 未被显式声明为 prop 的透传属性（如 `data-*`, `aria-*`, `title`, `class`） |
| **交互表单分类** | **基础配置** (标题、类型、方向等)<br>**组件特有** (表格列定义、表单校验)<br>**样式配置** (尺寸、配色) | **高级配置** (原生态 HTML 属性、自定义透传属性、透传 Class/Style) |
| **配置Setter类型**| Switch/Select/Input/Dynamic List/Code Editor | 动态键值对列表 (Key-Value Pair Table) |

---

### 8.3 Props/Attrs 侧边配置界面的交互方案对比

针对“选中组件后如何向用户展示与修改各种 Props/Attrs/Config”，探讨以下三种方案（即使暂未定论，也可作为后续版本选型对比）：

#### 方案 A：右侧固定抽屉/面板 (Fixed Right Setter Panel) —— **推荐（0.0.1 默认选型）**
- **交互方式**：点击画布中的某个组件，页面右侧或弹出固定抽屉/面板，展示分类 Tab（`属性 Props`, `样式 Style`, `事件 Events`, `JSON 源码 Preview`）。
- **优点**：符合主流低代码工具（如阿里 LowCode Engine、Formily）操作习惯；主画布不被遮挡；支持大空间配置复杂的“高端表格列设置”与“表单规则”。
- **缺点**：屏幕较小时可能压缩主画布视觉空间。

#### 方案 B：选中组件浮动悬浮框 (Floating Context Menu/Popover)
- **交互方式**：选中画布节点后，在节点正上方或正旁悬浮小面板，提供简易属性配置与删除/复制快捷按钮。
- **优点**：操作路径极短，视觉上下文直观。
- **缺点**：不适合配置过于繁杂的高端表格/表单属性（如数十列表格的列宽、对齐、插槽设置）。

#### 方案 C：双击大弹框 (Modal Configuration Dialog)
- **交互方式**：双击画布上的高端表格/表单，弹出一个居中的 Modal 对话框，使用 Step 步骤条或树结构配置表格/表单的深度属性。
- **优点**：界面空间极大，可容纳可视化表格列拖拽重排、关联数据源等极复杂的业务逻辑。
- **缺点**：阻断性强，无法做到“边配置边在主画布实时看渲染效果”。

### 8.4 0.0.1 推荐落地策略

综合考虑**代码工整性、组件解耦与用户体验**，0.0.1 版本采用 **“右侧固定抽屉 (Right Drawer) + 按物料类型动态加载 Setter”** 的架构：

1. **Setter 注册制**：
   - 每一种物料在 `registry` 中不仅注册组件本身，还注册其对应的 `setterComponent`（例如 `ProTableSetter.vue`, `ProFormSetter.vue`）。
2. **自动解析通用 Props/Attrs**：
   - 基础属性（如 `disabled`, `size`, `label`）使用通用 `CommonPropsSetter` 渲染。
   - 自定义 HTML 属性 `attrs` 使用通用 Key-Value 编辑器组件 `KeyValueSetter` 渲染。
3. **实时响应式联动 (Reactive Update)**：
   - 在右侧 Setter 中修改任何属性，Pinia store 中对应 `ComponentNode` 节点的 `props`/`attrs` 实时变动，主画布通过 Vue 3 响应式系统同步重绘预览，右侧底部的 JSON 预览区同步打印最新的 JSON 结构。
