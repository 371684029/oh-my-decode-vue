## 执行计划

### M1 — P1 收口（本轮）

1. **`errorMessage` 助手 + 收窄**：`@lowcode/shared` 新增 `errorMessage`（按「服务端 `response.data.message` > 字符串抛出物 > `Error.message` > 对象 `message`」提取）、`errorText`（同上 + 调用方兜底文案）、`errorStatus`、`isRecord`；47 处 `catch (err: any)` 全部改 `unknown`，前端兜底文案保持原中文不变。
2. **表达式分层**：`expression.ts` 拆为 `expression/tokenizer.ts`（词法）、`expression/evaluator.ts`（受限递归下降求值器 + `evaluateRawExpression` + `parsesCleanly`）、`expression/index.ts`（模板扫描门面）。7 个调用点 import 路径不变。
3. **designerStore 拆分**：以「**只抽不带 `this` 的代码**」为硬边界，拆出 `designerSchema.ts`（历史条目类型、主画布同源、历史 diff 前副本剥离、id 生成与树 id/target 重写）、`designerState.ts`（`createInitialState` + getter）、`designerNodeFactory.ts`（原子/黑盒/复合物料与图层工厂）。
4. **MaterialManager 拆分**：抽两个**自足** handler 簇成 composable —— `useMaterialVersions`（版本列表/回滚/归档/差异/fork/批量升级）与 `useMaterialIO`（文件与粘贴导入、Vue/HTML 导出）。

## 范围边界与执行纪律

- 不新增用户可见功能；不触碰冻结清单（v3.0 / v4.0 归属能力与锦上添花项）。
- **拆分纪律**：只抽不带 `this` 的代码，action 体一个字节不动。每次抽取配三道护栏 ——
  1. **独立性断言**：抽块内不得出现组件/store 作用域名；
  2. **尺寸区间断言**：超出预估即中止且**不写盘**；
  3. **action 计数断言**：拆分前后 action 数量必须完全一致（40 → 40）。
- **失败教训**：首次尝试用非贪婪正则 `.*?\n    },\n` 抽 action 体，越界匹配误删了相邻 action，导致 store 缺少 `addLayer` / `removeLayer` / `toggleLayerVisible` / `updateLayerProps` / `addCompositeFromMaterial` 五个方法。该次改动**整体回退**而非带病修复，随后改用上述纯函数边界重做。第 3 道护栏即源于此。
